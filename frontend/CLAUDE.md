# AI Market Dashboard — Frontend

## Что это
React фронтенд информационного дашборда по крипторынку.
Показывает свечи Binance с индикаторами, AI-комментарий к последней
закрытой свече и ленту новостей. **Не торговый терминал:** вердиктов
BUY/SELL/SKIP, уверенности, риска, позиций и кошелька на экране нет — сняты
в TASK-0001. Рамка: «триггеры, не команды». Границы — `../docs/VISION.md`.

## Стек
- React 19 + TypeScript
- Vite — сборщик
- styled-components — стили
- recharts — графики
- axios — HTTP запросы

## Типы (types/market.ts)
Зеркало `backend/src/market/market.types.ts` — интервалы, диапазоны,
`MIN_CANDLES`/`MAX_CANDLES` и формы ответов меняются в обоих файлах вместе.
- `Interval` — `1m 5m 15m 1h 4h 1d`; `Range` — `1h 4h 12h 24h 2w 1m 3m 1y`
- `isAllowed(range, interval)` — свечей в диапазоне от 12 до 5000 (как бэкенд;
  иначе он ответит 400). Порядок аргументов — диапазон, интервал; у
  `getCandles` — интервал, диапазон (как в URL)
- `nearestAllowed(range, interval)` — диапазон после смены интервала:
  допустимый остаётся, иначе ближайший по порядку вкладок (24ч→1д = 2нед)
- `MarketSeries` — ответ `/candles` (`candles` + `series`, `series[i].t ===
  candles[i].t`); `MarketView` — ответ `/view` (`latest`, `recent`, `closedAt`,
  `aiComment`)

## Ключевые решения
- Источник — закрытые свечи Binance через бэкенд, своей истории нет
  (`../docs/DECISIONS.md` 2026-10-20). Кнопки «обновить» нет: новая свеча
  приходит с опросом.
- `load()` — `getCandles` и `getView` через `Promise.allSettled`: ошибки
  графика и карточки раздельные. Упал `/view` (Groq, 502 «Binance не отдал
  свечей») — график остаётся, у карточки пометка «Карточка не обновилась: …».
  Баннер — только по ошибке свечей.
- Тексты ошибок: нет ответа — «Нет связи с бэкендом»; 502 — сообщение
  бэкенда («Binance недоступен»); другой код — «Бэкенд вернул ошибку (код N)».
- Токен запроса (`requestRef`) — поздний ответ после смены монеты,
  интервала, диапазона или следующего опроса в состояние не попадает.
- Данные показываются, только если они про текущие монету, интервал и
  диапазон (`chartShown`/`viewShown`): после переключения и отказа под
  баннером иначе висели бы чужие цены. Пока идёт запрос — блок пуст.
- Интервал и диапазон меняются одним обработчиком (`changeInterval`):
  React сводит оба `setState` в один рендер, недопустимая пара на бэкенд не
  уходит (замер CDP Network, TASK-0004.8: 0 ответов 400).
- Недопустимые вкладки периода погашены (`isAllowed` по текущему интервалу).
- `PriceChart` — ось X числовая по времени (`t` = время открытия свечи, мс).
  На дыре между соседними свечами больше 3 интервалов (остановка Binance)
  вставляется пустая точка — рвутся все серии, `connectNulls` нет. Дата в
  подписях и тултипе — на диапазонах длиннее суток. BB — одна `Area` по
  `bbRange` ([низ, верх] или `null`). Домен Y — по цене и BB с отступом 0.1%.
- Одна свеча — одна подпись по времени открытия (`formatCandleTime`):
  тултип и таблица «19:40», карточка «свеча 5м · 19:40–19:45»; дневная
  свеча — только дата («19 окт.»), её граница — полночь UTC.
- Первая загрузка в эффекте — через `Promise.resolve().then(load)`, не прямым
  вызовом (`react-hooks/set-state-in-effect`).

## Опрос
- `load()` раз в `min(интервал, 5 мин) + 10 с` (план TASK-0004, trade-off 9);
  таймер не выровнен по закрытию свечи — отставание экрана от 0 до периода
- При смене монеты, интервала или диапазона — немедленная перезагрузка
- Новая свеча → новый AI-комментарий на бэкенде (кэш по фактам свечи); на
  1м — раз в минуту на монету, принято (план TASK-0004, trade-off 6)

## Известное
- Подписи оси X на длинных диапазонах теснятся и повторяются, на оси Y —
  дробные значения: внешний вид, TASK-0003.
- `NewsPanel` — `try/finally` без `catch`: отказ `/news` даёт пустую ленту без
  индикации ошибки. Предсуществующий дефект, отдельный тикет.
