## Источник: CoinGecko (curl 2026-11-02, без ключа)
`GET https://api.coingecko.com/api/v3/coins/markets?vs_currency=usd&ids=bitcoin,ethereum,solana`
→ 200, массив из трёх объектов, `cache-control: max-age=30, s-maxage=60`.
Поля и типы — JSON `number` (не строка) или `null`:
`market_cap`, `fully_diluted_valuation`, `circulating_supply`,
`total_supply`, `max_supply` (ETH, SOL — `null`), `current_price`,
`last_updated` (ISO-строка, у всех трёх одна — `2026-11-02T15:04:48.000Z`).
Порядок массива — по капитализации, не по `ids`.
**FDV CoinGecko = `current_price × total_supply`, не × `max_supply`**
(сверка тем же ответом): BTC 77 749 × 20 105 365 = 1,5632·10¹² =
`fully_diluted_valuation` (1 563 683 738 020), а × 21 M было бы
1,633·10¹²; SOL 94,16 × 636 883 543 = 59,97·10⁹ ≈ FDV 60,00·10⁹
(расхождение — цена округлена в поле). Значит, у BTC FDV = капитализации,
хотя до лимита ~0,9 M монет. Неизвестный `id` — не
ошибка, его просто нет в массиве (поведение API; не проверено curl —
проверить в фикстуре). Ошибки лимита (429) — тело не снято.

## Риски изменения
- Лимит CoinGecko без ключа не закреплён; при опросе с нескольких
  вкладок без кэша на бэкенде — 429. Кэш бэкенда обязателен.
- Числа CoinGecko — `number`; разбор «не конечное или отрицательное → ошибка»
  нужен свой, `num` (`sources.ts:26`) требует строку.
- Цена капитализации ≠ цена Binance с графика (PRD, риски).
