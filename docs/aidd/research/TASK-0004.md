### Индикаторы — функции от массива цен, выборка отдельно

`price.service.ts:115-135`:
```ts
private async recentPrices(coinId: string): Promise<number[]> {
  const snapshots = await this.prisma.priceSnapshot.findMany({
    where: { coinId }, orderBy: { createdAt: 'desc' }, take: INDICATOR_WINDOW,
  });
  return snapshots.reverse().map((s) => s.price);
}
async getEMA(coinId: string, period: number): Promise<number | null> {
  const ema = lastValid(calcEMA(await this.recentPrices(coinId), period));
  return ema === null ? null : parseFloat(ema.toFixed(2));
}
```

## Риски изменения

1. **Объём при мелком интервале.** `fetchCandles` по образцу — 1000 свечей
   на запрос с паузой 200 мс (`backtest.service.ts:9-10`); год на 1м ≈ 526
   запросов ≈ 105 с только на паузы. Потолок числа свечей обязателен.
2. **Опрос × длинные диапазоны.** Опрос фронта каждые 5 мин 10 с
   (`App.tsx:97`) будет каждый раз тянуть весь диапазон с Binance — кэша
   свечей нет нигде в коде.
3. **Разогрев окна индикаторов.** `calcEMA`/`calcRSI`/`calcMACD` дают NaN в
   первых `period-1` / `period` / 33 точках (`indicators.ts`); для серии на
   графике нужно брать свечи с запасом слева от видимого диапазона, иначе
   начало графика без EMA/MACD. MACD signal валиден с индекса 33
   (`price.service.ts:144`).
4. **Окно индикатора ≠ окно 100 строк.** EMA/RSI Уайлдера зависят от длины
   ряда (план TASK-0002, trade-off 3). При расчёте по свечам с запасом
   значения сдвинутся относительно старых снимков — сверять с
   `technicalindicators` на том же ряду, как в TASK-0002.
5. **AI-кэш и интервал.** Кэш — по `coinId` (`market.comment.ts:13`): при
   переключении интервала одна запись монеты будет перетираться;
   прошлые значения во входе меняют хеш на каждом новом закрытии свечи.
   Каждое переключение интервала — новый вызов Groq.
6. **Цикл модулей.** Удаление шедулера снимает причину `forwardRef`
   (`price.module.ts:9`) — если оставить, не сломается; если убрать, модули
   нужно развязать аккуратно.
7. **`market.comment.spec.ts`** завязан на `MarketSnapshot` из Prisma (`:2`,
   `:29-30`); удаление модели из схемы сломает импорт типа.
8. **Удаление таблиц** — миграция Prisma; прошлый опыт: автогенерация
   переименования дала бы `DROP` (`DECISIONS.md`, 2026-10-07). Читать
   миграцию глазами.
9. **`price.service.spec.ts`** (7 тестов) проверяет выборку окна из
   `PriceSnapshot` — при переезде на свечи тест теряет смысл и
   переписывается; новый оракул — `technicalindicators` на известном ряду
   свечей.

- **Кэша свечей** нет нигде; **лимиты weight Binance** в коде не учтены
  (замер PRD: `klines` limit=1000 — weight 2).
- **Список интервалов** для селекта — в коде есть только
  `INTERVAL_MINUTES` бэктеста (`1m…1d`); набор для UI не определён.
- **Потолок числа свечей** на запрос / допустимые комбинации диапазон ×
  интервал — не определены.
- **`bandwidth` BB** считается только в `getBollingerBands`
  (`price.service.ts:192`), в `calcBB` его нет.
- **MA5 и тренд** как функции от массива — нет; живут только в
  `PriceService` поверх `findMany`.
- **Как AI получает «прошлые значения»** — в коде нет ни одного места,
  где комментарий видит больше одного снимка.
- Удалять ли таблицы `PriceSnapshot`/`MarketSnapshot` — PRD оставил на план.
