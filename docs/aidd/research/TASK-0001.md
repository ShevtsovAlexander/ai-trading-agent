## Как устроены смежные части

### Cron собирает цены ЧЕРЕЗ analyze — не напрямую

Ключевая связь, которую легко не заметить. Планировщик не обращается к
`PriceService` за сохранением цены — он зовёт `analyze()`:

```ts
// backend/src/price/price.scheduler.ts:15-30
@Cron('0 */5 * * * *')
async collectAndAnalyze() {
  for (const coin of coins) {
    await this.analyzeService.analyze({ market: coin.market, coinId: coin.id, volume: 1500 });
```

А запись в `PriceSnapshot` живёт внутри `getPrice()`, который `analyze()`
вызывает первым (`analyze.service.ts:46`):

```ts
// backend/src/price/price.service.ts:56-58
await this.prisma.priceSnapshot.create({
  data: { coinId, price, high, low },
});
```

**Следствие:** вся история цен наполняется побочным эффектом торгового
анализа. Уничтожение `analyze` без сохранения этой цепочки останавливает
сбор данных — а на `PriceSnapshot` стоят все индикаторы
(`price.service.ts:14, 64, 74, 97, 106, 127, 154, 211, 247`), график и
будущие фичи ROADMAP.

Второй писатель того же снимка — `GET /price/:coinId`
(`price.controller.ts:8-17` → `getPrice` → `create`): каждый HTTP-запрос
цены добавляет строку в историю. Фронт этот эндпоинт не вызывает
(`getPrice` объявлена в `api/trading.ts:21` и нигде не используется).

### Порядок операций в analyze(): факты → вердикт → БД → позиции

- `:34-56` — 10 параллельных `Promise.all` к `PriceService`, чистые факты.
- `:58-247` — вердикт (weighted confluence, контрарная коррекция).
- `:250-254` — `expectedValue`, единственный потребитель `dto.volume`.
- `:256-262` — вызов LLM, принимает `decision` и `reason` внутрь промпта.
- `:264-284` — сборка ответа.
- `:296-321` — `prisma.tradeDecision.create` — 22 поля.
- `:323-361` — позиции и кошелёк.

Блоки «факты» и «вердикт» разделены чисто: `:34-56` не зависит от `:58-247`.

### AI-слой: две точки входа, у каждой один потребитель

```ts
// backend/src/ai/ai.service.ts:34-40
async analyze(market, currentPrice, decision, reason, trend): Promise<string>
```

`analyze()` вызывается **только** из `analyze.service.ts:256`. Его промпт
(`ai.service.ts:46-58`) прямо просит торговую оценку: «Ты — AI trading
agent… Решение системы: ${decision}… Дай краткий анализ и оценку риска».

`complete()` (`ai.service.ts:70-89`) — универсальный вызов, у него два
потребителя: `digest.service.ts:67` и `news.translator.ts` (`:35` внедряет
`AiService`). Их переписывание промпта в `analyze()` не задевает.

### Модель и БД

`TradeDecision` (`schema.prisma:20-47`) — 22 поля, индекс `[coinId, createdAt]`
(`:46`). Индикаторы — nullable `Float?`, вердиктные поля — **NOT NULL**
(`decision String`, `confidence Int`, `riskScore Int`, `expectedValue Float`,
`reason String`, `aiReasoning String`, `:38-43`). При переименовании модели
и снятии полей это `DROP COLUMN`, не осложнённый nullability.

Миграции пишутся как обычный SQL Prisma (`migrations/20260524184036_add_position/migration.sql`),
провайдер postgres (`migration_lock.toml`). Конфиг — `backend/prisma.config.ts:6-14`,
схема `prisma/schema.prisma`, URL из `DATABASE_URL`.

БД в docker: `backend/docker-compose.yml` — контейнер `trading-agent-db`,
база `trading_agent`, том `postgres_data` (переименование БД вне scope PRD).

## Паттерны для переиспользования

### Кэш по хешу входа — готовый ответ на критерий 14 PRD

`DigestService` уже решает ровно ту задачу, что PRD ставит для AI-комментария
«на лету»: не звать LLM, если вход не изменился.

```ts
// backend/src/digest/digest.service.ts:11-12
// Кэш по хешу набора id: лента не изменилась → не гоняем Groq
private cached: { hash: string; digest: Digest } | null = null;

// :28-29
const hash = this.hashItems(items);
if (this.cached?.hash === hash) return this.cached.digest; // лента та же

// :74-80
private hashItems(items: NewsItem[]): string {
  const ids = items.map((i) => i.id).sort().join('|');
  return createHash('sha1').update(ids).digest('hex');
}
```

Плюс деградация без падения: модель молчит или бросила — отдаём прошлый
результат (`:33`, `:44`), а не ошибку.

## Риски изменения

1. **Обрыв сбора цен.** `PriceSnapshot` пишется внутри `getPrice()`
   (`price.service.ts:41,56`), а вызывает его cron через `analyze()`
   (`price.scheduler.ts:25`). Если при переработке `analyze` потеряется
   вызов `getPrice`, история цен молча перестанет наполняться — бэкенд
   при этом стартует, `/health` отвечает, ошибок в логах нет.
   Критерий 7 PRD («cron сбора цен работает») это ловит только при явной
   проверке появления новых строк в `PriceSnapshot`.

2. **Молчаливая деградация графика.** EMA/BB на `PriceChart` берутся из
   снимков (`PriceChart.tsx:257-261`). Если поля индикаторов перестанут
   писаться или сменят имена без правки фронта, график отрисуется — просто
   без линий. TypeScript это не поймает при `?? null`.

3. **Цикл модулей.** `forwardRef` в `price.module.ts:9` и
   `analyze.module.ts:11`. Переименование каталога с потерей одного из
