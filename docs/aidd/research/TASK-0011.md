## Как устроены смежные части

**Карточка рынка и её окно.** `getView` берёт 10 свечей выбранного
интервала и разогрев:

```ts
// market-data.service.ts:111-118
async getView(coinId: string, interval: string): Promise<MarketView> {
  const coin = this.coin(coinId);
  const iv = this.interval(interval);
  const { candles, series, closes } = await this.compute(coinId, iv, VIEW_CANDLES);
```

`compute` тянет `count + WARMUP` свечей (`:297`, `:305-310`), `WARMUP = 500`
(`market.types.ts:48`). Значит, на интервале `1d` карточка уже держит в
`closes` **510 дневных close** — ≈ 1,4 года. На других интервалах дневных
свечей в карточке нет.

**Кэш свечей** — ключ `монета|интервал|число свечей|openTime последней
закрытой` (`market-data.service.ts:301`), 50 записей FIFO (`:39`,
`:317-319`); не кэширует, если Binance ещё не отдал закрытую свечу
(`:314-321`). Для `1d` запись живёт сутки.

**Закрытость свечи** — по локальным часам с запасом 5 с:
`CLOSE_MARGIN_MS = 5000` (`:43`), `lastOpen` (`:244-247`). Дневная свеча
Binance закрывается в 00:00 UTC.

**Загрузка свечей** — `fetchClosedCandles` (`backend/src/binance/klines.ts:26-80`):
постранично по 1000 (`:6`), пауза 200 мс между страницами (`:7`, `:79`),
незакрытая отброшена (`:58`), вес — из заголовка последнего ответа
(`:51-52`). Ошибки не ловит (`:24`); переводит их `fetch` сервиса: 429/418
включают ограничитель, иначе `502 'Binance недоступен'` (`market-data.service.ts:252-286`).

**Ограничитель** режет только `getHistory` (`:178-180`); карточку и окно —
нет (`:44-46`, комментарий «основное окно и карточку не режем»).

**AI-комментарий** — промпт по `MarketView`, ключ кэша — хеш фактов
промпта, в т. ч. `trend` (`market.comment.ts:166-182`); системный промпт
прямо называет «тренд за 10 свечей» источником динамики (`:44-50`) и
запрещает утверждать «о периоде длиннее» (`:49-50`).

**Фронт.** Карточка получает `MarketView` целиком (`MarketStateCard.tsx:7-9`),
`App.tsx:71` грузит `getView(activeCoin.id, interval)` вместе со свечами,
`settled` — по `монета|интервал|диапазон` (`App.tsx:65`, `:74`, `:146`).
Данные карточки показываются, только если `view.coinId` и `view.interval`
совпадают с выбранными (`App.tsx:138`).

## Риски изменения

- **AI-комментарий теряет вход.** `market.comment.ts:44-50`, `:120` строят
  описание динамики на «тренде за 10 свечей»; ключ кэша `:171`. Удалить
  поле без решения — промпт с `undefined` или комментарий без динамики.
  Тест `market.comment.spec.ts:124` меняет факт через `trend` — после
  удаления проверит не то.
- **Фронт и бэкенд держат дубль типов** (`market.types.ts:12-13`) — менять
  синхронно, иначе фронт читает `data.trend` = `undefined`
  (`MarketStateCard.tsx:177` → `TREND_LABELS[undefined]` — пустая ячейка).
- **Режим не от интервала, а карточка — от интервала.** Сейчас всё в
  `/market/view` привязано к `interval` (кэш `:301`, `App.tsx:65`, `:138`).
  Если режим положить в этот ответ, на интервалах кроме `1d` нужен
  отдельный запрос дневных свечей, и смена интервала будет гасить/ждать
  то, что от интервала не зависит (скелетон по `settled`, `App.tsx:146`).
- **Вес Binance.** Карточку ограничитель не режет (`:44-46`); полная
  дневная история — 3 страницы на монету. Кэш на сутки (`:301`) снимает
  повтор, но первый запрос после закрытия дня — у всех трёх монет.
- **Пауза 200 мс между страницами** (`klines.ts:7`, `:79`) — полная история
  ≈ +0,4 с к первому ответу, если её тянуть синхронно.
- **SOL короче** — 2020-08-11; длинное окно правила съест часть истории
  (PRD, риски).
- **Сутки в кэше.** Режим меняется не чаще раза в день; но `CLOSE_MARGIN_MS`
  и «не кэшируем без закрытой свечи» (`:314-321`) — первые секунды после
  00:00 UTC режим считается без последнего дня и не кэшируется.

## Не найдено / требует уточнения

- **Правила режима в коде нет** — ни ADX, ни наклона MA, ни «эффективности
  движения». Есть только `calcTrend` (10 шагов) и его копия в бэктесте.
- **Дневной ряд вне `interval=1d` никто не запрашивает** — маршрута «всегда
  дневные свечи» нет (`market.controller.ts:14-43`: все три маршрута берут
  `interval` из запроса).
- **Тестов на `calcTrend` нет** (`indicators.ts:143`) — эталона у старого
  правила нет, сравнивать новый режим со старым нечем.
- **Внешнего эталона «правильного режима» нет** — только эталон формулы
  (например, `technicalindicators.ADX`, если правило из этого семейства).
  Ярлык проверяется замером на истории (PRD, критерий 6), не оракулом.
- Что подаётся в AI вместо `trend` — решение plan (PRD, открытые вопросы).
