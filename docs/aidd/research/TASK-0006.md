## Как устроены смежные части

**Окно бэкенда всегда «до сейчас».** `compute` считает конец от часов:
```ts
// market-data.service.ts:145-148
const step = INTERVAL_MS[interval];
const now = this.clock() - CLOSE_MARGIN_MS;
const lastOpen = Math.floor(now / step) * step - step;
const rangeStart = lastOpen - (count - 1) * step;
```
Запрос к Binance — с разогревом: `rangeStart - WARMUP * step … lastOpen`
(`:158-165`); ряды индикаторов на всём `all`, разогрев отрезан (`:180-199`).
Задать конец окна в прошлом сейчас нельзя — параметра нет (`:65-69`).

**Разогрев.** `WARMUP = 500` (`market.types.ts:48`), комментарий `:44-47`:
вес затравки `(25/27)^500 ≈ 2·10⁻¹⁷` — ниже округления. Значит, кусок,
посчитанный отдельно со своим разогревом, даёт те же значения, что и
длинный ряд — на этом держится тест `market-data.service.spec.ts:225`
(«1d … от старта разогрева не зависит»).

**Кэш.** Ключ `${coinId}|${interval}|${count}|${lastOpen}` (`:152`), FIFO на
50 записей (`:35, :206-208`); не кэшируется, если Binance не отдал последнюю
закрытую свечу (`:203-210`). Для куска в прошлом «точный до закрытия
следующей свечи» не нужен — исторические свечи не меняются.

**Лимит длины.** `isAllowed` — 12…5000 свечей (`market.types.ts:42-55`);
`getSeries` отвергает иное `400` (`:76-80`). Фронт гасит кнопки тем же
`isAllowed` (`PriceChart.tsx:215`), `nearestAllowed` подбирает диапазон при
смене интервала (`types/market.ts:60-74`, `App.tsx:106`).

**Binance.** `fetchClosedCandles` идёт страницами по 1000 вперёд, пауза
200 мс (`klines.ts:6-7, 29-68`), незакрытую свечу отбрасывает (`:46`),
защищён от несдвигающейся страницы (`:59-64`). Ошибки — наверх, сервис
превращает в `502 «Binance недоступен»` (`market-data.service.ts:166-171`).
Учёта веса (`x-mbx-used-weight`) в коде нет — grep пуст.

**Фронт: одно состояние графика.** `load()` перезаписывает `chart` ответом
целиком (`App.tsx:87`), опрос — `setInterval(load, …)` (`:116`). Показ — по
ключу монета/интервал/диапазон (`:126-133`). Таблица берёт последние 50
точек того же `series` (`IndicatorHistoryTable.tsx:14, 118`).

**Фронт: график.** `setData` всех серий на каждое изменение `data`
(`CandleChart.tsx:196-201`); `fitContent` — только при смене ключа
(`:215-219`); перекрестие ищет свечу в `Set` времён текущих данных
(`:227-236`). Подпись времени — `formatCandleTime` (`utils/candleTime.ts:7-18`):
для `1d` — день и месяц **без года** (`:13`), для остальных дата только при
`withDate`, а `withDate` задаёт кнопка диапазона (`PriceChart.tsx:177`).

**Разрывы.** `toChartData` вставляет пустую точку, если соседние свечи
дальше `3 × интервал` (`chartData.ts:29, 64-75`); у линии перед разрывом —
прозрачный «мост» (`:35, 65-68`).

## Риски изменения

1. **Объём «до листинга».** Замер Binance 2026-10-22 (`klines`
   `startTime=0`): первая свеча BTCUSDT и ETHUSDT — 2017-08-17, SOLUSDT —
   2020-08-11. До сегодня это ≈ 4,8 млн свечей BTC на 1м (≈ 9,2 года ×
   525 600), ≈ 965 тыс. на 5м, ≈ 80 тыс. на 1ч, ≈ 3,4 тыс. на 1д.
2. **Вес Binance.** Замер 2026-10-22: `klines` limit=1000 — weight 2
   (`x-mbx-used-weight-1m` растёт на 2 за запрос), лимит
   `REQUEST_WEIGHT` — 6000 в минуту (`exchangeInfo`). Вся история BTC 1м —
   ≈ 4 830 запросов ≈ 9 660 weight: больше минутного лимита; при паузе
   200 мс (`klines.ts:7`) — ≥ 16 мин подряд. Учёта веса в коде нет.
3. **Разогрев на стыке.** Каждый кусок тянет ещё 500 свечей слева
   (`market-data.service.ts:162`) — +50 % трафика при куске 1000. Без
   разогрева левая часть куска разойдётся с эталоном (PRD крит. 2).
4. **Стык кусков.** Окно сейчас якорится на `lastOpen` по часам (`:147`); если
   кусок «до T» и основной ответ посчитаны в разные моменты, граница может
   дать дубль или дыру → `toChartData` вставит ложный разрыв (`chartData.ts:64`)
   или lightweight-charts получит дубль `time` (бросает — `frontend/CLAUDE.md`
   «Известное»).
5. **Опрос перезаписывает всё.** `setChart(c.value)` (`App.tsx:87`) — после
   догрузки следующий опрос (раз в `min(интервал, 5 мин) + 10 с`, `:116-119`)
   вернёт только диапазон кнопки и сотрёт историю.
6. **`setData` целиком** (`CandleChart.tsx:196-201`) на сотнях тысяч точек —
   каждый опрос пересоздаёт все ряды; `bandPrimitive.ts:68` обходит все точки
   на каждой отрисовке. Производительность не замерялась.
7. **Позиция при префиксе.** Логический индекс бара сдвигается при добавлении
   слева; текущий код держит вид только потому, что `fitContent` не вызывается
   при том же ключе (`:215-219`) — сохранится ли видимая свеча при префиксе,
   не проверено.
8. **Подписи времени в глубокой истории.** `1d` — без года
   (`candleTime.ts:13`); остальные — дата только при `withDate` по кнопке
   (`PriceChart.tsx:177`): после прокрутки за сутки на 24ч перекрестие
   покажет время без даты.
9. **Ключ кэша** (`market-data.service.ts:152`) содержит `lastOpen` «сейчас» —
   для исторических кусков он бы протухал каждую свечу, хотя данные не
   меняются.
