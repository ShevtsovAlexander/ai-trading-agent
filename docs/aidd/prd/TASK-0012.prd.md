# TASK-0012: Расширенный Daily Read — рынок и новости в одном своде
Status: PRD_READY

## Контекст / идея
Хотелка №4 `docs/ROADMAP.md`: «**Расширенный Daily Read** — свод не только
новостей, но и рыночного состояния (цена + объём + новости в одном абзаце).
Развитие дайджеста.» Человек (2026-11-03) выбрал её следом за TASK-0011 и
разрешил пройти весь флоу без гейтов, с критиком: «выполни сам с критиком у
меня не спрашивай». Решения scope ниже приняты исполнителем и помечены.

Что есть (код, 2026-11-03):
- `DigestService` (`backend/src/digest/digest.service.ts`) — AI-свод только по
  заголовкам: топ-20 заголовков → Groq, «3-5 предложений», кэш по хешу id
  новостей; зовётся из `NewsService.refresh()` (cron раз в час) и **только
  если лента не пуста**. `GET /news/digest` → `{ summary, generatedAt,
  itemCount }`. Фронт — плашка «AI-свод» во вкладке «Инфополе».
- Тестов у дайджеста нет.
- Режим рынка (TASK-0011) — `MarketDataService.getRegime`, в AI-текст не
  подавался: связать — задача этого тикета (`DECISIONS.md` 2026-11-03).

Дешёвая проверка данных (curl 2026-11-03 17:00 UTC, `klines 1h`, 31 день
одним запросом, вес 2): BTC Δ24ч +0,30 %, объём 24 ч 1,08 млрд USDT, к
среднему суточному за 30 дней ×0,96; ETH +1,27 %, ×0,62; SOL +0,15 %, ×0,77.
Отношение объёма **в монетах** другое (ETH ×0,66, SOL ×0,88) — цена за месяц
менялась; «объём» берём в USDT (поле `quoteAssetVolume`).

## Проблема
AI-свод говорит только о новостях. Что при этом делал рынок — цена за сутки,
активность торгов, режим — надо собирать глазами из других блоков; связи
«новость ↔ движение» в одном месте нет. При этом LLM путает числа и знаки
(`backend/CLAUDE.md`, «Известное»; критик TASK-0004), так что просто
отдать модели свечи нельзя.

## Цель
Свод — один абзац: что было с рынком за сутки (BTC, ETH, SOL: цена,
изменение, объём к обычному, режим) и что в новостях; все числа посчитаны
кодом и видны рядом с текстом, модель только связывает их словами.

## User stories
- Как человек, открыв «Инфополе», я хочу одним абзацем понять, что за сутки
  было с рынком и о чём новости, чтобы не собирать картину из пяти блоков.
- Как человек, я хочу видеть числа, на которых построен текст, и время, на
  которое они посчитаны, чтобы проверить модель, а не верить ей.

## In scope
- Факты рынка по BTC, ETH, SOL, **посчитанные кодом** (решение исполнителя):
  цена последнего закрытого часа, изменение за 24 ч, объём за 24 ч в USDT и
  его отношение к среднему суточному объёму за 30 дней перед этим, режим
  рынка и сколько дней он держится (TASK-0011).
- Промпт свода: факты строками + заголовки; один абзац; числа — только из
  фактов; без рекомендаций.
- **Проверка ответа модели кодом**: число в тексте, которого нет в фактах, или
  слово-указание → текст отвергнут (остаётся прошлый свод).
- Свод пересобирается и при смене фактов, а не только ленты; при пустой
  ленте (фиды легли) — свод по рынку без новостей.
- Ответ `GET /news/digest` дополняется фактами и временем их расчёта.
- Фронт: под текстом свода — строка фактов по каждой монете и оговорка
  «числа — код, текст — модель».
- Отказ Binance по монете не роняет свод: монета без фактов, текст без неё.

## Out of scope
- Свод по отдельной монете, история сводов, рассылка.
- Деривативы, стакан, поля монеты в своде (возможное развитие).
- Новые источники новостей; исправление `NewsPanel` (лента грузится один
  раз, нет индикации ошибки — известный дефект).
- Объяснение причин движения («цена упала из-за…») как утверждение —
  модель может только поставить рядом, не связывать причинно.
- Смена модели или провайдера LLM.

## Критерии успеха
1. Факты каждой монеты равны независимому расчёту по свечам Binance
   (оракул — скрипт Python по curl) на тот же час.
2. Ответ модели с числом не из фактов или со словом-указанием не попадает в
   свод — известные ответы на подставных текстах.
3. Свод пересобирается при смене фактов при той же ленте; при пустой ленте
   строится по рынку.
4. На экране — текст, строка фактов по трём монетам с временем и оговорка;
   числа строки = ответу бэкенда.
5. Отказ Binance по одной монете — свод по двум, монета помечена; по всем —
   свод по новостям, как раньше.

## Риски и допущения
- **Модель в окружении агента недоступна** (Groq 403, TASK-0011): текст
  свода исполнитель живьём не увидит — тесты на подставных ответах модели,
  проверка текста — глазами человека.
- Проверка «числа только из фактов» отсекает и честные пересказы («втрое»,
  «рост на треть») — свод может чаще оставаться прошлым. Замерить нельзя без
  модели (см. выше).
- Свод раз в час (cron); факты внутри часа устаревают до часа — время
  расчёта на экране.
- Объём Binance спот — не весь рынок; отношение к 30 дням — к своему же
  среднему, не «высокий/низкий» в абсолюте.
- Новые запросы к Binance: 3 монеты × 1 запрос в час (вес 2) + режим (кэш).
