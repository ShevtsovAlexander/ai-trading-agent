# TASK-0014: Порядок в проекте — образец настроек, без неиспользуемой базы, автопроверка на GitHub
Status: PRD_READY

## Контекст / идея
Человек (2026-11-04) выбрал из `ROADMAP.md`, раздел Production-hardening:
«Навести порядок» одним тикетом: файл-образец настроек, убрать неиспользуемую
базу, автопроверка сборки на GitHub. На экране ничего не меняется.

Что есть сейчас (проверено 2026-11-04):
- **Образца настроек нет.** Бэкенд читает из настроек `GROQ_API_KEY`,
  `GROQ_MODEL`, `GROQ_REASONING_EFFORT`, `GROQ_TIMEOUT_MS`, `GROQ_MAX_RETRIES`
  и `DATABASE_URL` (`ai.service.ts:25-33`, `prisma.service.ts:11`). Фронтенд
  настроек из окружения не читает.
- **База не используется.** С TASK-0004 в неё никто не пишет и из неё никто не
  читает: Prisma упомянута только в своём модуле и в `app.module.ts`. При этом
  бэкенд пишет «Подключено к PostgreSQL», даже когда база не запущена.
- **Автопроверки на GitHub нет** (нет каталога `.github`).
- **Проверка кода на бэкенде сейчас не проходит:** 29 ошибок и 8 предупреждений
  ESLint в 7 файлах; 25 ошибок — форматирование, 4 — нет. Фронтенд чист.
  Команда `npm run lint` на обеих частях запускается с `--fix`: она сама правит
  файлы, поэтому такой же запуск на GitHub скрыл бы часть ошибок.

Связанное решение: `DECISIONS.md` 2026-10-20 отвергло удаление таблиц
`PriceSnapshot`/`MarketSnapshot` как необратимое ради чистоты схемы. Этот тикет
решение не отменяет: уходит код, данные остаются (см. In scope).

## Проблема
1. Чтобы запустить проект со стороны, нужно угадать настройки: списка нет.
2. README требует поднять базу, которая ничего не делает, а лог при старте
   сообщает о подключении, которого могло не быть. Код врёт о сути проекта.
3. Сломанная сборка или ошибка проверки кода попадает в `main` незамеченной:
   именно поэтому на бэкенде накопились 29 ошибок.

## Цель
Человек со стороны клонирует репозиторий, копирует образец настроек и запускает
дашборд без базы и Docker. Каждое изменение на GitHub проверяется автоматически.

## User stories
- Как человек со стороны, я хочу видеть список настроек с пояснениями, чтобы
  запустить проект, не читая код.
- Как разработчик, я хочу не поднимать базу, которая ничего не хранит, чтобы
  запуск был проще, а код и логи говорили правду.
- Как автор PR, я хочу видеть на GitHub, прошли ли сборка и проверка кода, чтобы
  не сливать сломанное в `main`.

## In scope
- **Образец настроек:** все настройки, которые читает код после удаления базы:
  что значит каждая, обязательна ли, какое значение по умолчанию. Без настоящих
  ключей.
- **Удаление базы из проекта:** код подключения, схема, зависимости, команды и
  файл запуска контейнера, инструкции о базе. Схема и миграции остаются в истории
  git.
- **Данные архива не трогаем:** Docker-том с таблицами на машине человека не
  удаляется, `DROP` не выполняется.
- **Автопроверка на GitHub** для фронтенда и бэкенда: сборка и проверка кода,
  которая находит ошибки, но ничего не исправляет сама.
- **Ноль ошибок и предупреждений проверки кода на бэкенде**, иначе автопроверка
  красная с первого дня. Правки без изменения поведения.
- **Документы:** `README.md`, `CLAUDE.md` (корневой, бэкенд), `ROADMAP.md`,
  `DECISIONS.md`.

## Out of scope
- Любые изменения на экране, новые функции и маршруты.
- Docker для всего проекта и проверки внешних зависимостей: отдельные пункты
  `ROADMAP.md`.
- Прогон тестов (jest) в автопроверке: в выбранном пункте только сборка и проверка
  кода. Кандидат на следующий тикет.
- Выкладка на сервер, сканеры безопасности, обновление зависимостей.
- Запрет слияния при красной проверке (настройка репозитория на GitHub, её делает
  человек при желании).
- Удаление данных архива и других локальных файлов человека (`backend/.env`
  остаётся как есть).

## Критерии успеха
1. **Запуск с нуля:** в чистой копии репозитория, без Postgres и Docker, по
   инструкции README бэкенд и фронтенд запускаются; дашборд показывает цены и
   график.
2. **Образец полон:** множество настроек в образце равно множеству настроек,
   которые читает код (сверка поиском по коду); настоящих ключей в файле нет.
3. **Базы нет:** поиск `prisma`, `postgres`, `DATABASE_URL` по коду и инструкциям
   находит только исторические записи (`DECISIONS.md`, `ROADMAP.md`, артефакты
   прошлых тикетов); ложной строки о подключении в логе нет.
4. **Поведение то же:** ответы всех 13 маршрутов до и после совпадают по статусу и
   структуре на монете `bitcoin`, успешном ответе и пустом ключе Groq (живая сверка);
   все существующие тесты проходят. Другие монеты, ответы с ошибками, текст модели и
   потеря поля только у части элементов списка этой сверкой не покрыты; при закрытии
   это указывается явно.
5. **Данные целы:** Docker-том с архивом на месте после завершения тикета.
6. **Автопроверка настоящая:** на PR проверка зелёная; на нарочно сломанном коде
   отдельно для ошибки сборки и ошибки проверки кода, на фронтенде и бэкенде —
   красная. Файлы проверка не меняет.
7. **Проверка кода чиста:** на бэкенде и фронтенде 0 ошибок и 0 предупреждений
   при запуске без автоисправления.

## Риски и допущения
- **Ключ Groq (проверено живым запуском 2026-11-04):** настройки нет — бэкенд
  падает при старте; настройка пустая — бэкенд работает, цены и графики есть,
  комментарий и перевод не генерируются (Groq отвечает 401). Строка ключа в
  образце обязательна, даже если значение пока пустое.
- **4 ошибки проверки кода не исправляются автоматически:**
  `indicators.spec.ts:203,206` и `news.translator.ts:29,111`. Предупреждений 8, в
  том числе `main.ts:23`. Правки затрагивают работающий код, поэтому критерий 4 и
  тесты должны пройти после них.
- **Сверка автопроверки требует пуша.** Критерий 6 проверяется только на GitHub;
  пуш и PR — с разрешения человека.
- Допущение: прошлые снимки цен в базе человеку не нужны для работы дашборда
  (никто их не читает с TASK-0004); сам архив при этом сохраняется.

## Открытые вопросы
Нет: развилка по данным архива решена в сторону необратимо безопасного варианта
(данные не трогаем). Человек может изменить это решение на гейте.
