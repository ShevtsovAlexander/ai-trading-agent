# План: TASK-0010 — поля монеты (CoinGecko)

PRD — `docs/aidd/prd/TASK-0010.prd.md`, research — `docs/aidd/research/TASK-0010.md`.

## Подход

Бэкенд одним запросом CoinGecko `coins/markets` берёт все три монеты,
строго разбирает и держит снимок 60 с на все монеты сразу (один запрос в
минуту к CoinGecko при любом числе вкладок). `GET /coin/:coinId` отдаёт
поля одной монеты. Фронт опрашивает раз в 60 с и показывает карточку
«Монета» в левой колонке под карточкой рынка.

```
 CoinGecko coins/markets ──► разбор ──► снимок 3 монет ──► /coin/:coinId
 (ids=bitcoin,ethereum,solana)  строго    кэш 60 с          поля одной
```

## Контракты

### `GET /coin/:coinId`
400 — неизвестная монета. Источник один, поэтому отказ CoinGecko = 502 с
`message` (его показывает `classify` → `errorText`, `api/errors.ts:18-21`):
«CoinGecko недоступен» / «CoinGecko: превышен лимит запросов» (HTTP 429) /
«CoinGecko не отдал монету» (монеты нет в массиве).

```ts
interface CoinFields {
  coinId: string;
  market: string;            // COINS[coinId].market
  marketCapUsd: number;      // market_cap, > 0
  fdvUsd: number | null;     // fully_diluted_valuation (CoinGecko: цена × total)
  circulating: number;       // circulating_supply, > 0, монеты
  total: number | null;      // total_supply, монеты
  max: number | null;        // max_supply; null — лимита нет
  updatedAt: number;         // last_updated, мс
}
```
Разбор: обязательные — конечное `number` > 0; необязательные — `null`
или конечное `number` > 0; иначе ошибка с именем поля («CoinGecko: поле
X …»). `updatedAt` — `Date.parse` ISO, не число — ошибка. Ответ не массив —
ошибка.

## Поток данных
- Снимок: `{ at, value: Map<coinId, CoinFields> | Error }`, ключ один на
  все монеты. Свежий (< 60 с) — ответ из него, в том числе ошибка (повтор
  к упавшему CoinGecko не чаще раза в минуту — критерий 6 PRD).
- Ответ без одной монеты — успешный снимок: 60 с эта монета получает
  502 «CoinGecko не отдал монету», остальные — данные (критик T2; повтор
  не чаще раза в минуту, критерий 6).
- Параллельные запросы при пустом кэше ждут один промис (`inflight`) —
  три вкладки на старте дают один запрос, не три.
- Фронт: опрос 60 с; худший случай отставания ≈ 60 + 60 с CoinGecko-кэша
  + 60 с наш = ~3 мин — для капитализации приемлемо.

## Показ
- Капитализация, FDV — `$1,56 трлн` / `$279,27 млрд`; предложение —
  `20,11 млн BTC`; доля «в обращении X % от максимума» только при `max`.
- `max === null` → «лимита нет»; `fdvUsd === null` → «нет данных».
- Подпись «CoinGecko · обновлено HH:MM» (`updatedAt`, местное время).
- Оговорка (фикс. текст): оценка CoinGecko по средней цене бирж, может не
  совпадать с ценой Binance на графике; FDV у CoinGecko — цена × всего
  выпущено (не максимум); это масштаб монеты, не указание к сделке.

## Trade-offs
1. **Один запрос на три монеты, кэш общий** — против запроса на монету:
   в 3 раза меньше обращений к лимиту без ключа. Отвергнуто: по монете.
2. **502 на весь ответ** — источник один, поля в ответе нечем частично
   заполнить (в отличие от деривативов, `derivatives.types.ts:40-45`).
3. **FDV как у CoinGecko**, без своего пересчёта по `max` — PRD требует
   совпадения с источником (критерий 1); формулу говорит оговорка.
4. **Доля от максимума — на фронте**: деление для показа, не данные.
5. **Место — левая колонка под карточкой рынка** (research «Дальние
   связи»: таблица справа растянется). Отвергнуто: отдельная строка во
   всю ширину — пять чисел растянулись бы по 1280 px.
6. Ошибка кэшируется 60 с — как деривативы (`derivatives.service.ts:161`).

## Риски
- Лимит без ключа (research, «Риски»): закрыт кэшем + `inflight`.
- Тело 429 не снято (research, «Не найдено») — 429 распознаём по HTTP
  статусу ошибки axios, не по телу.
