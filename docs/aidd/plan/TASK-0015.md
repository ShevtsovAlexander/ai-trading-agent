## Подход
Отдельный модуль `liquidations` по образцу «Компаний-держателей»: один внешний источник, своя карточка
под графиком открытых позиций. История у Coinalyze, у нас только кэш в памяти (принцип
`docs/DECISIONS.md` 2026-10-20). Показываем только закрытые свечи: как во всём проекте, и такие
значения можно сверить. Фронт ничего не считает: ряд и сумму за 24 часа отдаёт бэкенд.

Экран:
```
ЛИКВИДАЦИИ  BTC/USDT                                   1Д  1М  1Г
За 24 часа: лонги $X · шорты $Y  (?)

лонги ▲ столбики вверх / шорты ▼ столбики вниз

```

## Контракты
`GET /liquidations/:coinId?period=1d|1m|1y`. Период по умолчанию на экране — `1m`.

| Период | Шаг Coinalyze | Закрытых свечей |
|---|---|---|
| `1d` | `15min` | 96 |
| `1m` | `1hour` | 720 |
| `1y` | `daily` | 365 |

```ts
type LiqPeriod = '1d' | '1m' | '1y';

interface LiqPoint {
  t: number;               // открытие свечи, мс UTC, на сетке шага
  longUsd: number | null;  // null: ни одна биржа не отдала запись за эту свечу
  shortUsd: number | null;
}

interface Liquidations {
  coinId: string;
  market: string;
  period: LiqPeriod;
  stepMs: number;
  exchanges: ({ exchange: Exchange } | { exchange: Exchange; error: string })[]; // всегда три
  last24h: { longUsd: number; shortUsd: number; from: number; to: number };
  points: LiqPoint[];      // полная сетка, по возрастанию t
}
```

Символы — research, таблица USDT-контрактов. Запрос: заголовок `api_key`, `from`/`to` в секундах,
`convert_to_usd=true`.

Ошибки:
| Случай | Ответ |
|---|---|
| Неизвестная монета или период | 400, без запроса к Coinalyze |
| Ключ не задан или пуст | 502 «Не задан ключ Coinalyze (COINALYZE_API_KEY в backend/.env)», без запроса |
| 401/403 от Coinalyze | 502 «Coinalyze отклонил ключ» |
| 429 | 502 «Coinalyze: превышен лимит запросов»; пауза по `Retry-After`, без него 60 с |
| Прочий отказ, все биржи пусты | 502 «Coinalyze недоступен» |
| Биржи нет в ответе или её ряд пуст | 200, `error` в её поле, сумма без неё |

## Поток данных
```
Браузер (опрос 5 мин, ключ монета|период)
  → GET /liquidations/:coinId?period
    → кэш `монета|шаг` (до закрытия следующей свечи + 60 с; ошибка и неполный ряд 60 с; один запрос в полёте)
      → Coinalyze: 3 символа одним вызовом
    → всегда два ряда: выбранный период и 15 минут для суммы за 24 часа
  ← готовый ряд, last24h, состояние бирж
```
Нагрузка: 3 монеты × 3 шага = не больше 9 вызовов при пустом кэше, лимит 40 в минуту (research).
Вкладки делят один кэш. Нового кода в `DerivativesService` нет.

## Trade-offs
1. **Значок с подсказкой** вместо постоянной подписи — решение человека. Цена: не заметивший значок
   не узнает о неполноте. Поэтому постоянно видны биржи, источник и оговорка. Подсказка своя, а не
   `title`: тот не открывается клавиатурой (research).
2. **Только закрытые свечи** — как `binance/klines.ts`. Цена: на 1Г нет текущего дня, а сумма за 24
   часа отстаёт до 16 минут (шаг + минута запаса). Незакрытая свеча отвергнута: значение меняется между запросами (research,
   риск 7), сверить его нельзя.
3. **Сумма за 24 часа — всегда 96 свечей по 15 минут**, на всех периодах, чтобы число не менялось от
   вкладки. Цена: один лишний кэшированный вызов. Конец окна — на экране: «За 24 часа до ЧЧ:ММ» (правка по критику: столбики могут кончаться раньше суммы).
4. **USDT-контракты**, как в `derivatives.types.ts:8-10`. Монетные отвергнуты: у BTC 75 млн USD против
   1,83 млрд за 30 дней, а сверка с OKX шла только по USDT (research).
5. **Столбики вверх и вниз серым.** Наложение отвергнуто: скрывает меньшую сторону. Зелёный и красный
   отвергнуты: они значат рост и падение (research, риск 6), а ликвидация лонга — ни то, ни другое.
6. **Нет записи — `null`, пустое место, а не 0.** На полной сетке, иначе ось схлопнет промежуток
   (`OpenInterestChart.tsx:66-68`). В легенде: «нет записей». Отличить затишье от сбоя нельзя, это
   написано в оговорке.
7. **Слова «лонги» и «шорты»** — по PRD, хотя панель ставки их избегает (`frontend/CLAUDE.md:201`).
   Поэтому оговорка их поясняет.
8. **Свой разбор чисел.** Менять `num` нельзя: от него зависят стакан и деривативы (research).
9. **Отдельный модуль**, а не `DerivativesService`: тот не защищён от одновременных запросов
   (`derivatives.service.ts:36-39`) и не знает о ключе.
10. **Скрипт сверки в репозитории:** запускается в разные моменты, scratchpad стирается.

Оговорка на экране (фиксированный текст, правит человек при ревью):
> Ликвидация — биржа принудительно закрыла ставку. Лонги — ставки на рост (столбики вверх), шорты — на
> падение (столбики вниз). Пустое место — источник не записал ликвидаций ни на одной бирже: это может быть
> и затишье, и сбой. Если замолчит одна биржа, столбики просто станут ниже. Доллары примерные: источник
> пересчитывает их по цене свечи, а не самой ликвидации. Сумма за 24 часа — по завершённым 15-минутным
> свечам, столбики графика могут кончаться раньше. Сравнивать суммы разных монет нельзя: полнота данных у
> них разная. Не прогноз и не указание к сделке.

## Риски (research, «Риски изменения» и «Дозамер»)
- **Суммы неполные неизвестно насколько**, форма всплесков и перевес могут искажаться. Закрывают
  значок и оговорка, не код.
- **Эталон неточен:** OKX тоже может отдавать не все события; его сверка не доказывает точность.
- **Ключ в журнале (риск 5):** пишем только статус и текст, тест проверяет отсутствие значения ключа.
- **Секунды и миллисекунды (риск 2):** перевод в одном месте, `sources.ts`.
- **Закрытые точки могут меняться:** проверено только за 90 с, перепроверка в T8.
- **Условия и лимит сервиса** могут смениться; отказ виден на экране, остальные блоки независимы.
