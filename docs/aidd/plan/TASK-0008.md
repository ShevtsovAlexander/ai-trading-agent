# План: TASK-0008

График открытых позиций (OI) Binance + OKX + Bybit за 30 дней, цена линией,
переключатель «По дням» / «По часам». PRD — `docs/aidd/prd/TASK-0008.prd.md`,
research — `docs/aidd/research/TASK-0008.md` (включая «Дозамер перед
планом»). Ветка — `feat/TASK-0008-oi-chart` от `main` `98865f5`.

## Подход

Бэкенд собирает **готовый ряд** на одной сетке моментов: каждая точка — сумма
OI трёх бирж в USD в один и тот же момент T и цена Binance в T. Фронт его
только рисует — сложение, перевод единиц и сдвиги меток живут в одном месте,
где есть jest и фикстура реальных ответов (паттерн TASK-0007: строгий разбор
и оракул на фикстуре, research «Паттерны»).

Ключевые решения из замера (research «Дозамер»):
1. **Момент точки, а не метка биржи.** Binance и Bybit — метка = снимок в T;
   OKX — метка T = значение в T + шаг, его самая свежая строка — живое
   значение незакрытого периода и отбрасывается. После сдвига OKX у трёх бирж
   720 общих часов и 30 общих дней.
2. **Bybit в USD — по своей mark-цене в T** (open mark-свечи Bybit с началом
   в T): так же, как Binance (своя mark в T) и OKX (своя цена снимка).
3. **Цена на графике — спот Binance**, close свечи, которая **закрылась в T**
   (открыта в T − шаг). Оракул PRD 3 — `klines`.
4. **Точка есть, только если в T есть все учтённые биржи** — иначе дыра, не
   сумма по двум (PRD 2). Биржа, упавшая целиком, исключается из суммы явно:
   в ответе её ошибка, на экране «без OKX — сумма неполная» (PRD 5).
5. **Ленивые часы:** фронт спрашивает только выбранный шаг; по умолчанию
   «По дням» — почасовых запросов нет, пока не нажата кнопка (PRD 8).

```
биржи ──► sources.ts (история OI, mark Bybit) ─┐
спот Binance ──► klines.ts (fetchClosedCandles) ┼► oi-history.ts (сетка T, сумма, дыры)
                                                └► DerivativesService.openInterestHistory (кэш)
                                                     └► GET /derivatives/:coinId/open-interest?step=
фронт: useOpenInterestHistory(coin, step) ─► OpenInterestChart (OI + цена, легенда-разбивка)
```

## Контракты (сигнатуры, типы, форматы)

### `GET /derivatives/:coinId/open-interest?step=1d|1h`

```ts
type OiStep = '1d' | '1h';

interface OiPoint {
  t: number;                                    // момент снимка, мс UTC, на сетке шага
  totalUsd: number;                             // сумма учтённых бирж в T
  byExchange: Partial<Record<Exchange, number>>; // USD каждой учтённой биржи в T
  price: number | null;                         // close спота Binance свечи, закрытой в T; null — нет свечи
}

interface OpenInterestHistory {
  coinId: string;
  market: string;                               // 'BTC/USDT'
  step: OiStep;
  exchanges: ({ exchange: Exchange } | { exchange: Exchange; error: string })[]; // всегда binance, okx, bybit
  priceError: string | null;                    // спот недоступен — линия цены пуста
  points: OiPoint[];                            // по возрастанию t; дыра — шаг между соседями > step
}
```

- `400` — неизвестная монета (как `derivatives.service.ts:64-69`) или `step`
  не `1d`/`1h`.
- Отказ биржи — `{ exchange, error }` с текстом `UNAVAILABLE`
  (`derivatives.service.ts:34-38`), биржа выпадает из суммы всех точек.
  Все три упали — `points: []`, 200.
- Bybit упал только по mark-цене — Bybit `{ error: 'Bybit недоступен' }`
  (без цены его OI в USD не посчитать).

### Источники (`sources.ts`)

```ts
interface OiRow { t: number; coin?: number; usd?: number } // t — метка биржи, как есть
fetchOiHistoryBinance(http, symbol, period: '1d'|'1h', from: number): Promise<OiRow[]> // usd = sumOpenInterestValue
fetchOiHistoryOkx(http, instId, period: '1Dutc'|'1H', from: number): Promise<OiRow[]>  // usd = oiUsd (4-й элемент)
fetchOiHistoryBybit(http, symbol, interval: '1d'|'1h', from: number): Promise<OiRow[]> // coin = openInterest
fetchMarkBybit(http, symbol, interval: 'D'|'60', from: number, to: number): Promise<Map<number, number>> // open по началу свечи
```

Каждая выгружает метки ≥ `from` (окно + один шаг запаса), страница обязана
сдвигаться, OKX/Bybit — код ошибки в теле. Binance — назад по `endTime`
(research: `startTime` не задаёт начало выдачи, старше 30 дней — `-1130`).

### Сборка (`oi-history.ts`)

```ts
buildOiSeries(input: {
  step: OiStep; now: number;
  binance: OiRow[] | null; okx: OiRow[] | null; bybit: OiRow[] | null; // null — биржа упала
  bybitMark: Map<number, number> | null;
  spot: Candle[] | null;                                               // свечи шага, t = open
}): OiPoint[]
```

1. Моменты: Binance `t`; Bybit `t`; OKX `t + step`, строки с `t + step > now`
   отброшены (живая).
2. Окно: `T > now − 30 дн.` и `T ≤ now`.
3. Точка — только моменты, где есть **все** не-`null` биржи (и mark Bybit,
   если Bybit учтён). Bybit USD = `coin × mark(T)`.
4. `price` = close спот-свечи с `t = T − step`.

## Поток данных

1. Фронт: `step` в `App` (по умолчанию `'1d'`); `useOpenInterestHistory(coin,
   step)` грузит при смене монеты/шага и опрашивает раз в 5 мин.
2. Бэкенд: кэш по `coinId|step`. Ответ без ошибок, где последняя точка = последний
   ожидаемый момент (`floor(now/step)·step`), живёт до следующего момента
   + 2 мин; иначе — 60 с (повтор к упавшей бирже, отставание публикации).
3. Промах кэша: `allSettled` — Binance, OKX, Bybit + mark Bybit, спот
   `fetchClosedCandles` (`klines.ts:26`, символ из `COINS`); затем
   `buildOiSeries`.
4. Фронт рисует: OI — правая шкала, цена — левая; дыра — пустая точка
   (как `chartData.ts:118-134`). Перекрестие → легенда: дата, сумма,
   Binance / OKX / Bybit, цена.

Запросов на промах кэша (замер): по дням — 1+1+1+1+1 = 5; по часам —
2+8+4+1+1 = 16 на монету.

## Trade-offs

1. **Сборка ряда на бэкенде** — а не на фронте из трёх сырых ответов: сдвиг
   OKX, mark Bybit и пересечение моментов проверяются jest на фикстуре;
   на фронте оракула нет (UI-тесты не пишем).
2. **Отдельный маршрут, не поле в `/derivatives/:coinId`** — у истории свой
   кэш (час/сутки против 30 с снимка), шаг в запросе и 16 запросов на
   промах; встроенная в снимок, она тормозила бы опрос ставки раз в 60 с.
   Существующие типы и панель TASK-0007 не меняются (PRD out of scope).
3. **Bybit по своей mark в T**, а не по споту Binance: две другие биржи
   считают USD своей ценой в момент снимка (замер). Отвергнуто: цена спота
   Binance — смешение бирж; текущий `tickers` — только для «сейчас».
4. **Цена — спот Binance, а не mark фьючерса:** главный график и PRD 3
   («закрытия свечей Binance», оракул `klines`) — спот; `fetchClosedCandles`
   уже есть. Отвергнуто: `getCandles` с фронта — свечи там с меткой
   открытия и индикаторами; совмещать моменты пришлось бы на фронте, и
   `1h×1m` занимал бы кэш главного графика (research «Дальние связи»).
5. **Дыра вместо суммы по двум** (PRD 2). Биржа, упавшая целиком, —
   исключена из всех точек с явной пометкой; иначе один сбой OKX стирал бы
   весь график. Это повтор правила панели TASK-0007 («· без OKX»).
6. **Отдельная карточка в `DerivativesRow` под панелью**, а не внутри
   `DerivativesPanel`: панель рисуется только при `derivatives.data`
   (`App.tsx:213`) — отказ `/derivatives` прятал бы график, а у графика
   свои загрузка, ошибка и шаг. Визуально — тот же раздел, заголовок
   «Открытые позиции · 30 дней». **Отступление от PRD «в панели» — на
   согласование.**
7. **Две шкалы (OI справа, цена слева)** — у величин разный порядок
   (млрд USD против десятков тысяч); общая шкала сплющила бы цену.
8. **Опрос 5 мин** — новые точки раз в час/сутки; бэкенд-кэш до следующего
   момента, лишних запросов к биржам нет.
9. **Ограничителя запросов нет** — как TASK-0007 (DECISIONS 2026-10-27):
   заголовка веса у `futures/data` нет (research), с кэшем — ≤ 16 запросов
   на монету и шаг в час. Лимиты не измерены — проверка в T1.
   *Поправка T4:* полный ряд держится до следующего момента + 10 мин
   (выдержка OKX); пока ряд неполный (hh:00–hh:10, отказ, дыра) — повтор
   раз в 60 с на запрос с фронта, по 16 запросов. При опросе фронта раз в
   5 мин — 2–3 выгрузки в час на монету и шаг.
10. **Без отдельных линий бирж** — разбивка только в легенде (PRD out of scope).

## Риски (ссылки на research)

- **Соглашение о метках у бирж может поменяться** (research «Дозамер»): сдвиг
  OKX — константа кода. Защита — живая сверка T3 (цена пересчёта OKX = mark
  в T + шаг) и запись в `backend/CLAUDE.md` «Известное».
- **Тест-фейк по подстроке URL** (`derivatives.service.spec.ts:23-32`) — новые
  URL обязаны получить свои фикстуры; фейк расширяется до T2.
- **Лимиты OKX `rubik`** не измерены, 8 запросов подряд по часам; задержка
  между страницами — как `REQUEST_DELAY_MS` (`sources.ts:9`), замер в T1.
- **Граница 30 дней у Binance** (`-1130` на `startTime` старше) — выгрузка
  по `endTime` назад до `from`, не глубже.
- **Публикация точки с задержкой** — последняя точка может отставать на шаг;
  кэш тогда 60 с (поток данных, п. 2).
- **`HTTPS_PROXY` в терминале агента** — живые проверки через `env -u
  HTTPS_PROXY` (`backend/CLAUDE.md` «Известное»).
- **PRD 7 без точного оракула:** последняя точка (00:00 или начало часа) и
  текущий OI снимка в разные моменты; проверка — расхождение в пределах
  движения OI за этот промежуток, не равенство.
