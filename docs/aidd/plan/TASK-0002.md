# План: TASK-0002 — индикаторы по свежим данным, честный график

Основа — `docs/aidd/research/TASK-0002.md` (дальше «R»), PRD —
`docs/aidd/prd/TASK-0002.prd.md`.

**Решения человека (2026-10-14):**
1. RSI считается **по Уайлдеру** — как `technicalindicators`.
2. Оракул — **функции бэктеста**: формулы выносятся в общие чистые
   функции, которые уже сверяются с библиотекой в spec.

## Подход

Сейчас в проекте две копии формул: `PriceService.get*` (сломанные, без
тестов) и `BacktestService.calc*` (верные, под оракулом) — R, «Главное», п.2.
Чиним не копию, а убираем дублирование:

1. Чистые `calcEMA / calcRSI / calcMACD / calcBB` переезжают из
   `backtest.service.ts:313-414` в общий модуль `indicators`. Бэктест
   импортирует их оттуда. Чистый перенос, без изменения поведения —
   `VISION.md`: «не рефактори и не добавляй фичи одновременно».
2. `calcRSI` переводится на сглаживание Уайлдера; RSI-тест получает
   настоящий `expect` вместо `toBeGreaterThanOrEqual(0)`
   (`backtest.indicators.spec.ts:110`).
3. `PriceService.get*` берёт свежие строки (`desc` + `reverse`, образец —
   `getTrend`, `price.service.ts:70-78`), вызывает общую функцию и отдаёт
   её последний элемент. Своей математики в `PriceService` не остаётся.
4. Связку «выборка → разворот → последний элемент» проверяет отдельный
   spec на `PriceService`: фейковая Prisma честно сортирует по `orderBy` и
   режет по `take`, эталон — `technicalindicators` на последних N ценах.
5. В `captureSnapshot` запись цены идёт **до** чтения индикаторов —
   убирает гонку (R, «Риски» п.4).
6. График: BB — полосой через `bbRange`, домен Y учитывает BB, ось X —
   временная, длинные дыры видны разрывом.

## Контракты

### `backend/src/indicators/indicators.ts`
Сигнатуры переносятся **как есть** из бэктеста (R, «Паттерны»):
```ts
export function calcEMA(prices: number[], period: number): number[]
export function calcRSI(prices: number[], period = 14): number[]
export function calcMACD(prices: number[]): { macd: number[]; signal: number[]; histogram: number[] }
export function calcBB(prices: number[], period = 20): { upper: number[]; middle: number[]; lower: number[]; bandwidth: number[] }
```
Инвариант: длина результата = длина `prices`; невалидные индексы — `NaN`.
Валидны: EMA с `period-1`, RSI с `period`, MACD-линия с 25, signal и
histogram с 33, BB с `period-1` (комментарии `backtest.service.ts:309-389`).

### RSI по Уайлдеру — определение, совпадающее с эталоном
Сверено с исходником `technicalindicators` (`lib/Utils/AverageGain.js`,
`lib/oscillators/RSI.js`):
- первое `avgGain/avgLoss` (индекс `period`) — простое среднее первых
  `period` дельт;
- далее `avg = (avg·(period−1) + текущее) / period`;
- `avgLoss = 0` → 100; `avgGain = 0` → 0; иначе `100 − 100/(1+RS)`.

**Эталон округляет RSI до 2 знаков** (`RSI.js`: `toFixed(2)`), средние —
нет (точность в конфиге не задана). Поэтому для RSI допуск —
**абсолютный ≤ 0.005**, а не относительный `TOLERANCE = 0.0001`: при RSI
около 50 округление само даёт до 1e-4 относительно, и тест флапал бы.

### `PriceService` — внешний контракт не меняется
`getEMA(coinId, period): Promise<number|null>`, `getRSI(coinId, period=14)`,
`getMACD(coinId): Promise<{macd, signal, histogram} | null>` — те же
сигнатуры и то же округление `toFixed(2)`. Потребитель один —
`market.service.ts:33-36` (R, «Дальние связи»).

Внутри:
```
findMany({ where:{coinId}, orderBy:{createdAt:'desc'}, take: INDICATOR_WINDOW })
→ reverse() → prices[] → calcX(prices) → последний элемент
→ NaN или нехватка данных → null
```
`INDICATOR_WINDOW = 100` строк — одна константа на три метода вместо
`period*3`, `period+10`, `26*3` (`price.service.ts:105`, `:126`, `:153`).
Минимумы данных, после которых не `null`: EMA — `period`, RSI —
`period+1`, MACD — 34 (signal валиден с 33).

### `price.service.spec.ts` — фейковая Prisma
`priceSnapshot.findMany({ where, orderBy, take })` — **честно** фильтрует по
`coinId`, сортирует по `orderBy.createdAt` и режет `take`. Иначе тест не
отличит `asc` от `desc` и будет зелёным на баге. Эталон: `ti.EMA/RSI/MACD`
на последних `INDICATOR_WINDOW` ценах хронологически, последний элемент.

## Trade-offs

**1. Общий модуль формул, а не исправление копии в `PriceService`.**
Выбрано: перенос из бэктеста. Оракул уже есть (`backtest.indicators.spec.ts`),
и после переноса он покрывает обе стороны — бэктест и дашборд.
Отвергнуто: чинить `get*` на месте и писать им отдельный оракул — третья
копия логики сверки и две копии формул, которые снова разойдутся.

**2. ⚠️ Уайлдер меняет и бэктест.** Бэктест использует RSI как фильтр входа
(`backtest.service.ts:501-511`: `rsi > 70` / `rsi < 30` блокируют вход).
После перехода на общую функцию результаты прогона `POST /backtest/run`
сдвинутся, а цифры в `docs/RESEARCH.md` (winRate ~37%) сняты на простом
среднем. Выбрано: одна формула RSI в проекте, факт фиксируется в
`DECISIONS.md`; выводы RESEARCH не перепроверяем — RSI там лишь фильтр,
вес сигнала дают EMA/MACD/тренд (`:480-495`).
Отвергнуто: держать простой RSI для бэктеста отдельной функцией — это
ровно та двойственность формул, которую тикет убирает.
**Гейт: если хочешь сохранить бэктест неизменным — скажи до T2.**

**3. Окно 100 строк, а не «вся история».** Эталон считает по всей
истории, наша выборка — 100 строк (≈8 ч при шаге 5 мин). EMA и RSI
Уайлдера от длины окна зависят, но spec сравнивает на том же массиве,
так что расхождения нет. На живом экране значения отличаются от
TradingView в пределах сходимости. Отвергнуто: брать всю историю — на
3 мес это 25 920 строк × 4 запроса каждые 5 мин ради сотых долей.

**4. Гонка — последовательным `await`, а не одним запросом цен.**
Выбрано: `getPrice` первым, остальные параллельно — минимальная правка,
методы не меняют форму. Отвергнуто: один `findMany` на все индикаторы в
`captureSnapshot` — экономит 6 запросов, но переделывает границу между
сервисами. Отдельный тикет, если понадобится.

**5. График: дыры честно, без `connectNulls`.** Сейчас EMA соединяются
через пропуски (`PriceChart.tsx:317`, `:328`), BB — нет. Выбрано: единое
правило для всех серий — без `connectNulls`, плюс разрыв на дыре во
времени больше 15 мин (3 шага крона) через вставку пустой точки. Цена
тоже рвётся. Отвергнуто: оставить категориальную ось — 62 дня
пропуска выглядят как 5 минут (PRD, п.4).

**6. Старые снимки не пересчитываются** (PRD, «Не делаем»). На диапазонах
2нед/1мес/3мес будет видна ступенька: плоские EMA до починки, живые после
(R, «Дальние связи»). Принимаем, фиксируем в `DECISIONS.md`.

## Риски

- **False-green оракула** (R, «Риски» п.1–2). Закрывается тремя мерами:
  RSI-тест сначала запускается красным на простом среднем, и только потом
  меняется формула (T2); spec `PriceService` запускается красным на
  текущем `asc`-коде до правки (T3); фейковая Prisma обязана уважать
  `orderBy`.
- **Тихая порча при `desc` без `reverse`** (R, п.3) — ловит spec из T3:
  эталон считается по хронологии.
- **Дыры в данных** (R, п.5): окно в 100 строк склеит цены через простой
  бэкенда. Не чиним — вне PRD. Фиксируем в `DECISIONS.md`.
- **`GET /price/:coinId` пишет строки вне сетки** (R, «Источник строк»)
  — окно «в точках» ≠ окно во времени. Вне тикета, уже в «замечено рядом».
- **Производительность `matchSnapshots`** (R, п.6) — не трогаем, данных мало.
- **Временная ось меняет `tickFormatter` и тултип** (R, п.7) — они
  переходят с ISO-строки на число; закладываем в T7.
- **Живые проверки требуют Docker и запущенного бэкенда** — Docker сейчас
  не запущен (R, «Не найдено»). Задачи T5 и T8 — с человеком.
