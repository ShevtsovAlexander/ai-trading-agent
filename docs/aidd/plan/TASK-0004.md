# План: TASK-0004

## Подход

Источник цен — закрытые свечи Binance по запросу; бэкенд ничего не
накапливает. Один путь данных на всё: **свечи → ряды индикаторов → (график,
таблица, карточка, AI)**. Формулы — существующие чистые функции
`indicators.ts` (R, «Индикаторы — функции от массива цен»): меняется только
источник массива.

Порядок — **сначала добавить, потом убрать**: новые модули и эндпоинты
бэкенда рядом со старыми (T1–T5), фронт переезжает на них (T6–T8), и только
потом удаляются крон, запись цен и старые маршруты (T9). На каждом шаге
дашборд работает.

График в этом тикете — **минимум** (решение человека 2026-10-19): свечи
как источник, селект интервала, EMA/BB по рядам. Внешний вид не трогаем —
«график как на TradingView» возможно сменит библиотеку (PRD TASK-0003,
вопрос 6), полировка recharts здесь была бы выброшена.

## Контракты

**Интервалы и диапазоны** (`market.types.ts`, зеркально во фронте):
```ts
type Interval = '1m' | '5m' | '15m' | '1h' | '4h' | '1d';
type Range = '1h' | '4h' | '12h' | '24h' | '2w' | '1m' | '3m' | '1y';
const MAX_CANDLES = 5000;   // свечей в диапазоне, без разогрева
const WARMUP = 200;         // свечей слева от диапазона для разогрева индикаторов
```
Комбинация допустима, если `rangeMs / intervalMs <= MAX_CANDLES`; иначе
бэкенд — `400`, фронт — кнопка неактивна. Примеры: 24ч×5м = 288 ✓,
3мес×5м = 25 920 ✗, 3мес×1ч = 2160 ✓, 1г×4ч = 2190 ✓, 1г×1ч = 8760 ✗.

**Свеча и точка ряда:**
```ts
interface Candle { t: number; open: number; high: number; low: number; close: number; volume: number } // t = openTime, ms
interface SeriesPoint {
  t: number; close: number;
  ema9: number | null; ema21: number | null; rsi: number | null;
  macd: number | null; macdSignal: number | null; macdHistogram: number | null;
  bbUpper: number | null; bbMiddle: number | null; bbLower: number | null; bbBandwidth: number | null;
}
```
`null` — периоду не хватило свечей (NaN из `indicators.ts`, как `lastValid`
`price.service.ts:13-16`). Округление — `toFixed(2)`, как сейчас.

**`GET /market/candles/:coinId?interval=5m&range=24h`** →
`{ coinId, market, interval, range, candles: Candle[], series: SeriesPoint[] }`
— только свечи диапазона (разогрев отрезан), `series[i].t === candles[i].t`.

**`GET /market/view/:coinId?interval=5m`** → `MarketView`:
```ts
interface MarketView {
  coinId: string; market: string; interval: Interval;
  closedAt: number;            // closeTime последней закрытой свечи
  price: number; previousPrice: number;
  ma5: number | null; trend: 'up' | 'down' | 'flat';
  latest: SeriesPoint;         // последняя закрытая свеча
  recent: SeriesPoint[];       // 5 последних закрытых, старые → новые (вход AI)
  aiComment: string | null;
}
```
**Ошибки:** Binance недоступен → `502 { message: 'Binance недоступен' }`;
недопустимая комбинация/интервал/монета → `400`.

## Поток данных

```
Binance klines ──fetchClosedCandles──▶ MarketDataService
   (WARMUP + диапазон, кэш до закрытия следующей свечи)
        │ close[] ──calcEMA/RSI/MACD/BB/SMA/Trend──▶ series (разогрев отрезан)
        ├─▶ GET /market/candles → PriceChart (свечи + EMA/BB) + IndicatorHistoryTable
        └─▶ GET /market/view   → MarketStateCard + MarketComment(recent) → aiComment
Фронт: интервал + диапазон → load() (два запроса, токен) → опрос раз в min(интервал, 5 мин) + 10 с
```
Записи в БД нет ни на одном шаге.

## Trade-offs

1. **Через бэкенд, а не фронт напрямую** (решение человека, PRD вопрос 1).
   Одни свечи для графика, карточки и AI; кэш в одном месте. *Отвергнуто:*
   фронт → Binance (CORS открыт, PRD «Допущение») — индикаторы пришлось бы
   считать дважды или гонять свечи с фронта на бэк для AI.
2. **Разогрев 200 свечей, а не окно 100 строк.** Вес начала ряда после 200
   шагов: EMA21 (20/22)^200 ≈ 5·10⁻⁹, RSI Уайлдера (13/14)^200 ≈ 4·10⁻⁷,
   MACD-EMA26 (25/27)^200 ≈ 2·10⁻⁷ — ниже округления до 0.01. Поэтому
   последняя точка графика и карточка совпадают при любом диапазоне, а
   значения не зависят от того, откуда начали (R, риск 4). *Отвергнуто:*
   100 — EMA26 (25/27)^100 ≈ 5·10⁻⁴, на цене ~$80k это заметно в сотых.
3. **Потолок 5000 свечей и запрет комбинаций** (R, риск 1). 5000 + 200 —
   6 запросов к Binance (weight 12), recharts выдерживает. Год на 1м не
   даём — как TradingView ограничивает глубину мелкого интервала.
   *Отвергнуто:* прореживание на бэкенде — подменяет свечи, которых нет.
4. **Таблицы БД не удаляем.** Перестаём писать и читать; схема и данные
   остаются, миграции нет. Удаление — отдельным шагом, если понадобится
   (миграции читаются глазами, `DECISIONS.md` 2026-10-07; R, риск 8).
   *Отвергнуто:* `DROP` сейчас — необратимо ради чистоты схемы.
5. **Кэш свечей — до закрытия следующей свечи.** Набор закрытых свечей
   меняется только на закрытии, так что кэш точный, а не «примерно свежий».
   Ключ: монета + интервал + диапазон + openTime последней закрытой.
   Размер — ограничен (старые ключи вытесняются). *Отвергнуто:* TTL по
   времени — либо устаревает, либо бесполезен.
6. **AI видит 5 последних закрытых значений** (решение человека, вопрос 6)
   и интервал; кэш — по монете и интервалу. Факты меняются на каждом
   закрытии свечи → на 1м интервале Groq зовётся при каждом опросе (раз в
   ~70 с). Принимаем в духе `DECISIONS.md` 2026-10-07 (вызов на опрос —
   принято), фиксируем.
7. **`calcTrend`/`calcSMA` — в `indicators.ts`** (`calcBandwidth` не
   нужна — `calcBB` уже отдаёт `bandwidth`; решение 2026-10-20, T2), не в
   сервисе (R, «Не найдено»: MA5 и тренд живут только поверх `findMany`).
   Тренд переносится построчно из `getTrend` (`price.service.ts:81-102`) —
   внешнего эталона у правила «ups > downs × 1.5» нет, теста не пишем.
8. **Новый `klines.ts`, бэктест не трогаем.** Перевод бэктеста на общий
   клиент — рефакторинг рядом с фичей (`VISION.md`, «не рефактори и не
   добавляй фичи одновременно»). Дубль — в «Замечено рядом».
9. **Опрос раз в `min(интервал, 5 мин) + 10 с`.** На 1м интервале опрос
   раз в 5 мин показывал бы данные 5-минутной давности.

## Риски

- **Binance — единственный источник** (PRD «Риски»). Отказ → 502 →
  баннер на фронте; старые числа без пометки не показываем (критерий 6).
- **Разогрев на старте истории:** свечей до начала торгов пары нет —
  первые точки с `null`. Для BTC/ETH/SOL на глубине 1 года не возникает.
- **Цикл модулей** `forwardRef` (R, риск 6) — уходит вместе с шедулером в
  T9; развязывать аккуратно, проверка — старт приложения.
- **`market.comment.spec.ts`** привязан к `MarketSnapshot` (R, риск 7) —
  переписывается в T5, до удаления чего-либо.
- **Фейк HTTP в `klines.spec.ts`** обязан применять `startTime`/`endTime`/
  `limit` как Binance — фейк, отдающий всё подряд, = false-green
  (урок `price.service.spec.ts:27`).
- **Старые снимки в БД** больше нигде не показываются — «История
  индикаторов» теперь по свечам; мусор TASK-0002.5 уходит с экрана сам.
- **Живые проверки требуют сеть до Binance и запущенный бэкенд** —
  T10 с человеком.
