# План: TASK-0009 — Стакан сейчас: крупные лимитные заявки на графике

PRD — `docs/aidd/prd/TASK-0009.prd.md`, research — `docs/aidd/research/TASK-0009.md`.

## Подход

Бэкенд по запросу берёт два стакана спота (Binance `depth` 5000, OKX
`books-full` 5000), складывает их по **ступеням цены** фиксированного шага
на монету, оставляет только зону, которую видят **обе** биржи, и отдаёт
N = 10 крупнейших ступеней с каждой стороны. Фронт раз в 20 с берёт снимок
и рисует полосы у правого края области свечей своим примитивом серии (как
заливка BB), разбивку по биржам — плашкой при наведении на полосу.

Своей истории нет: снимок живёт в кэше 15 с и выбрасывается
(`DECISIONS.md` 2026-10-20, «данные по запросу»).

```
 Binance depth ─┐   ступени шага S    общий охват    N крупнейших
                ├─► (сумма монет) ──► обеих бирж ──► с каждой ──► /orderbook/:coin
 OKX books-full ┘   по стороне        (min края)     стороны       кэш 15 с
```

## Контракты (сигнатуры, типы, форматы)

### `GET /orderbook/:coinId`
400 — неизвестная монета. Отказ биржи — в её поле, не 502 (как
`/derivatives`, research «Деривативы: сборка ответа»).

```ts
type BookExchange = 'binance' | 'okx';

interface Wall {
  from: number;            // нижняя граница ступени, USDT
  to: number;              // from + step
  coin: number;            // сумма объёма в монетах
  usdt: number;            // Σ цена × объём уровней ступени (точно, не coin × середина)
  byExchange: Partial<Record<BookExchange, number>>; // монеты; биржа без заявок в ступени — нет ключа
}

interface OrderBookSnapshot {
  coinId: string;
  market: string;          // 'BTC/USDT'
  at: number;              // мс, часы бэкенда после ответа обеих бирж
  mid: number;             // середина Binance (свечи — Binance); Binance упал — OKX
  step: number;            // шаг ступени, USDT
  coverage: { bid: number; ask: number };  // общая граница охвата, цены
  exchanges: ({ exchange: BookExchange; at: number } | { exchange: BookExchange; error: string })[]; // всегда binance, okx
  bids: Wall[];            // ≤ 10, по убыванию usdt
  asks: Wall[];            // ≤ 10, по убыванию usdt
}
```
Обе биржи упали — `bids`/`asks` пусты, ошибки в `exchanges`. `at` Binance —
часы бэкенда при ответе (у Binance нет времени в ответе, research риск 4), OKX — `ts`.

### Источники (`orderbook/sources.ts`)
```ts
interface Book { bids: [number, number][]; asks: [number, number][]; full: { bid: boolean; ask: boolean }; at: number }
fetchDepthBinance(http, symbol: string, clock = Date.now): Promise<Book>  // /api/v3/depth?limit=5000; at = clock() после ответа (критик T1)
fetchBookOkx(http, instId: string): Promise<Book>                    // /api/v5/market/books-full?sz=5000
```
`full.bid = bids.length < 5000` — биржа отдала сторону целиком (у SOL на
Binance 4695 уровней, research «Внешние данные»): её края для охвата нет.
Разбор строгий: цена > 0, объём ≥ 0, `code !== '0'` у OKX — ошибка,
порядок уровней проверяется (покупки по убыванию, продажи по возрастанию).

### Сборка (`orderbook/walls.ts`)
```ts
buildWalls({ binance: Book | null, okx: Book | null, step: number, n: number }): {
  mid: number; coverage: { bid: number; ask: number }; bids: Wall[]; asks: Wall[]
}
```
1. `mid` — середина лучших цен Binance, иначе OKX.
2. Край охвата стороны у биржи — её самая дальняя цена (если сторона не
   `full`). Общий край — **ближайший к mid** из краёв ответивших бирж.
3. Уровень учитывается, если он на своей стороне от mid (покупки `< mid`,
   продажи `> mid`; research риск 6) и не дальше общего края.
4. Ступень — `floor(price / step) · step`. Ступень, которую край режет
   пополам, отбрасывается (неполная).
5. Сумма монет и `Σ цена × объём` по ступени, разбивка по биржам; сорт по
   `usdt`, первые `n`.

`BUCKET_STEP`: bitcoin 10, ethereum 1, solana 0.05 USDT (≈ 0,013 / 0,044 /
0,053 % от цены 2026-11-02; не мельче шага OKX BTC 0.1 — research риск 3).

## Trade-offs

1. **Сложение бирж — ступени фиксированного шага на монету** (выбрано)
   против: уровни как есть (у BTC шаги 0.01 и 0.1 почти не совпадают —
   сумма «на одной цене» пустая, research риск 3); шаг в % от цены (сетка
   плывёт с ценой — между снимками стена прыгает по ступеням). Фиксированный
   шаг — сетка стабильна, подписан «ступень $10».
2. **Только общий охват двух бирж** (выбрано) против: весь охват + пометка
   «здесь только Binance». Дальше края одной биржи сумма тихо становится
   одной биржей (research риск 2) — пометку на каждой полосе легко не
   заметить. Цена: у ETH теряется ~1,5 % охвата Binance. При отказе биржи —
   охват ответившей и пометка «без OKX — сумма неполная».
3. **Разделение сторон по mid Binance** (выбрано) против: стороны каждой
   биржи как есть. У бирж разная цена (~$5 у BTC, research риск 6): без
   общего mid продажа OKX может встать ниже свечи Binance, и критерий 3
   PRD ложен. Потеря — уровни в щели между ценами бирж, для стен ничтожно.
4. **Вес Binance — без общего ограничителя** (выбрано) против: вынести
   ограничитель из `MarketDataService` в общий сервис. Вес в заголовке —
   общий по IP (research «Дальние связи»): догрузка истории увидит вес
   стакана в следующем же ответе `klines`. Рефактор ограничителя — отдельный
   цикл (VISION: «не рефактори и не добавляй фичи одновременно»). Защита —
   кэш 15 с: ≤ 4 снимка/мин на монету = 1000 веса из 6000. 429/418 на
   `depth` — ошибка Binance в поле, повтор после истечения кэша.
5. **Опрос 20 с, кэш 15 с** против: 5 с (вес ×4) / 60 с. Замер ROADMAP:
   9 из 10 крупнейших заявок стоят минуту — 20 с хватает, время снимка на
   экране.
6. **N = 10 на сторону**, константа (PRD Out of scope: настройки N нет).
7. **Полосы в области свечей у правого края, полупрозрачные** против:
   область шкалы цены (`priceAxisPaneViews`) — она ~60 px, длину не
   прочитать; против: отдельный столбец рядом с графиком — другая шкала
   цены, выравнивание руками. Цена: полосы ложатся поверх последних свечей
   (`fixRightEdge`, research риск 7) — поэтому прозрачность и длина ≤ 25 %
   ширины. Окончательно — глаз человека в T6.
8. **Без `autoscaleInfo`** — шкала не растягивается на стакан (у SOL до
   −80 %, research «Дальние связи»). Полосы вне видимой цены не рисуются;
   плашка пишет «ещё K за краем графика».
9. **Разбивка — плашкой по перекрестию** (цена под курсором → ступень), не
   `hitTest` примитива: перекрестие уже подписано (`CandleChart.tsx:346-362`),
   `hitTest` не проверен на этом графике (research «Не найдено»).
10. **Хелперы разбора — `export` из `derivatives/sources.ts`** против:
    перенос в общий файл (рефактор) / копия (две правды). Тело не меняется.

## Риски (ссылки на research)

- Охват по монетам разный (риск 1): у SOL 10 крупнейших могут быть за
  краем видимого → плашка «за краем», не растяжение шкалы.
- Ступень на дневных свечах тоньше пикселя → минимальная толщина полосы
  2 px; соседние ступени сливаются — проверка глазом T6.
- Два запроса — два момента (риск 4); подпись — одно время `at` бэкенда.
- Тяжёлый ответ (риск 8): наружу отдаётся ≤ 20 ступеней, сырые 20 000
  уровней остаются на бэкенде.
- Лимит OKX `books-full` не замерен (research «Не найдено») — замер в T1.
- Наведение на тонкую полосу: ступень ищется по цене под курсором с
  допуском ±2 px — проверка глазом.
