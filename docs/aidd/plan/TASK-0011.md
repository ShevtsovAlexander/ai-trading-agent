# План: TASK-0011 — режим рынка по дневным свечам

## Подход

Режим — **ADX(14) Уайлдера по дневным свечам Binance** и направление по
+DI / −DI:

- ADX ≥ порога входа и +DI > −DI → **тренд вверх**;
- ADX ≥ порога входа и −DI > +DI → **тренд вниз**;
- иначе → **боковик**.

Почему ADX, а не своё правило:
1. **Есть внешний эталон формулы** — `technicalindicators.ADX` уже в
   проекте (research, «Паттерны»: `backend/package.json:63`,
   `lib/directionalmovement/ADX.js`). Отдаёт `{ adx, pdi, mdi }` (проверено
   2026-11-03: на 60 свечах — 33 точки, первая на индексе 27 = 2·14 − 1).
   Правило «наклон MA» или «эффективность движения» пришлось бы проверять
   своей же копией — false-green (`CLAUDE.md`, «Тесты — только с внешним
   оракулом»).
2. Это общепринятая мера **силы** движения, отдельно от направления —
   ровно вопрос «тренд или боковик». Человеку объяснима одной фразой
   («сила движения 0–100, от 25 — направленное»), не чёрный ящик
   (`VISION.md`, «AI не чёрный ящик»).

**Пороги и залипание решает замер (T1), не план.** Кандидаты:
(а) один порог 25 — вход и выход на одной черте; (б) **с запасом**: вход в
тренд при ADX ≥ 25, выход в боковик при ADX < 20 (между 20 и 25 режим
держится прежний). (б) гасит дёрганье у черты (PRD, риски), но дату начала
и ярлык тогда задаёт вся история, а не один день. Контракт ниже держит оба
порога; при (а) они равны. **Если замер покажет, что ни (а), ни (б) не
видят очевидных эпизодов или дёргаются — СТОП** (PRD, критерий 6).

Режим считается **по всей дневной истории от листинга** (BTC/ETH с
2017-08-17, SOL с 2020-08-11 — research, «Данные»): ≈ 3 страницы Binance на
монету раз в сутки. Так дата начала текущего режима точна при любой
длине серии, а разогрев Уайлдера не нужно подбирать — ряд один и тот же
у бэкенда и у эталона.

Режим — **отдельным маршрутом и отдельным блоком**, не в `/market/view`:
карточка привязана к интервалу (кэш `market-data.service.ts:301`,
`App.tsx:65`, `:138`, `:146`), режим — нет (PRD, решение 2). Поле «Тренд»
из карточки и из AI-промпта уходит.

## Контракты

```ts
// backend/src/indicators/indicators.ts
// Ряды длиной close.length; NaN до индекса 2·period − 1 у всех трёх
// (DI тоже — эталон отдаёт их только вместе с ADX; решение человека, T2).
// Сглаживание Уайлдера, как technicalindicators.ADX.
export function calcADX(
  high: number[], low: number[], close: number[], period = 14,
): { adx: number[]; pdi: number[]; mdi: number[] };

// backend/src/market/regime.ts
export type Regime = 'up' | 'down' | 'range';
export interface RegimePoint { t: number; adx: number; pdi: number; mdi: number }
// enter — порог входа в тренд, exit — порог выхода (exit ≤ enter; равны —
// без запаса). Точки — от старых к новым, без NaN (отрезает вызывающий).
// Возвращает ярлык каждого дня и индекс начала текущей (последней) серии.
export function classifyRegime(
  points: RegimePoint[], enter: number, exit: number,
): { labels: Regime[]; since: number };

// backend/src/market/market.types.ts
export interface MarketRegime {
  coinId: string;
  market: string;           // 'BTC/USDT'
  regime: Regime;
  adx: number;              // последней закрытой дневной свечи, 2 знака
  pdi: number;
  mdi: number;
  enter: number;            // порог входа (25)
  exit: number;             // порог выхода (20 или 25 — по итогам T1)
  since: number;            // openTime первого дня текущего режима, мс
  days: number;             // дней в текущем режиме, включая последний
  closedAt: number;         // closeTime последней закрытой дневной свечи
}
```

`GET /market/regime/:coinId` → `MarketRegime`; `400` — неизвестная монета
(`market-data.service.ts:140-145`), `502` — Binance недоступен или отдал
меньше `2·14` свечей (как `getView`, `:119-121`).

**Направление при ADX ≥ порога и `pdi === mdi`** — режим держится
прежний (на дневных данных с 2 знаками — редкость; T1 считает, сколько раз).

## Поток данных

```
Binance klines 1d (startTime 0 → последняя закрытая)
  → MarketDataService.getRegime: fetch (:252) → calcADX → classifyRegime
  → кэш `regime|монета|lastOpen дня` до закрытия следующего дня
  → GET /market/regime/:coinId
  → useMarketRegime (опрос 5 мин, токен, монета) → MarketRegimePanel
```

- Кэш на сутки: после 00:00 UTC + 5 с первый запрос монеты тянет историю
  заново (3 страницы, вес 2 каждая — research, «Данные»; пауза 200 мс между
  страницами `klines.ts:7`, ≈ +0,4 с к первому ответу). Не кэшировать,
  если Binance ещё не отдал закрытый день (`:314-321`).
- Ограничитель запросов режим не режет — как карточку (`:44-46`).
- Опрос 5 мин: данные меняются раз в сутки, смену после полуночи увидим
  ≤ 5 мин спустя; чаще — лишний трафик к своему бэкенду (не к Binance —
  там кэш).
- Смена интервала режим не перезапрашивает и скелетон не показывает.

## Trade-offs

1. **ADX, а не своё правило** — выбран за внешний эталон и объяснимость.
   Отвергнуты: наклон MA (эталона наклона нет), «эффективность движения»
   Кауфмана (в `technicalindicators` нет — эталон своей копией), старый
   `calcTrend` на днях (эталона нет, `indicators.ts:143`). Цена: ADX
   запаздывает сильнее — сглаживание дважды по 14 дней. Скажем на экране.
2. **Пороги — замер T1, утверждает человек.** 25 / 20 — привычные
   значения из литературы по ADX, не доказанные на нашей истории.
3. **Вся история от листинга, а не 500 дней разогрева.** Дата начала
   серии при запасе (б) зависит от прошлого; при окне в 500 дней длинный
   боковик мог бы начаться «за краем». Цена — 3 страницы раз в сутки.
4. **Отдельный маршрут и блок, а не поле в `/market/view`.** Иначе на
   интервалах кроме `1d` пришлось бы тянуть дни внутри карточки, а смена
   интервала гасила бы скелетоном то, что от интервала не зависит
   (research, «Риски»). Цена — четвёртый блок в левой колонке и ещё один
   запрос. Отклонение от решения 1 PRD по месту: режим **заменяет** поле
   «Тренд» по смыслу, но показан рядом, а не в той же ячейке — нужно
   место под числа, порог, дату и оговорку.
5. **AI-комментарий: тренд убираем, режим не подаём.** Комментарий — про
   5 свечей интервала, промпт запрещает говорить «о периоде длиннее»
   (`market.comment.ts:49-50`); дневной режим это правило нарушил бы на
   1м. Связать режим с текстом — задача следующего тикета (Daily Read).
   Цена — модель теряет короткий «тренд»; динамика 5 свечей у неё остаётся
   с посчитанными изменениями (`:100-147`).
6. **`calcTrend` удаляем из `indicators.ts`** — живых вызовов после правки
   нет, бэктест держит свою копию. Мёртвый код без эталона не держим.

## Риски

- **Правило не видит эпизодов или дёргается** — СТОП после T1 (PRD,
  критерий 6). Экран не строим.
- **Расхождение с эталоном на старте ряда** — T2 сверяет на всей истории,
  а не только на хвосте. (Итог T2: затравка у `technicalindicators` —
  книжная, как у Уайлдера; «свои правила» было неверно — критик T2.)
- **AI теряет вход** (research, «Риски»): правки `:44-50`, `:120`, `:171` —
  одной задачей с тестом `market.comment.spec.ts:124`.
- **Дубль типов** фронт/бэк (`market.types.ts:12-13`): `trend` убрать в
  обоих в одной задаче, иначе `TREND_LABELS[undefined]` — пустая ячейка.
- **Дыры Binance** на дневках (остановки биржи — `klines.ts:22-23`): день с
  дырой — короткая свеча, ADX считается как есть; эталон получит те же
  свечи.
- **Первые секунды после 00:00 UTC** — день ещё не отдан, режим без
  последнего дня, не кэшируется (`:314-321`); блок покажет `closedAt`
  прошлого дня — честно.
- **SOL короче** — 2300 дней против 3000; на ADX(14) не влияет, на
  статистику замера — да (T1 считает по каждой монете отдельно).

## Отклонения при реализации (решения человека, 2026-11-03)

- **Один порог 25** вместо `enter`/`exit`: `classifyRegime(points,
  threshold)`, в ответе — `threshold` (замер T1: запас 25/20 хуже).
- **`calcADX`: DI тоже NaN до `2·14 − 1`** — эталон раньше не отдаёт (T2).
- **`calcTrend` удалён в T5**, а не в T2 — до T5 у него был живой вызов.
- **NaN в ADX/DI любого дня — 502** «ADX не определён: в начале истории нет
  направленного движения», не молчаливый ярлык (критики T2–T4).
- **`adx` в ответе — отбрасыванием до 2 знаков** (`floor2`), DI —
  округлением: «ADX 25,00 · боковик» невозможен (критик T4).
- **Показ**: тикер и «Binance · дневные свечи» — в шапке блока, «день
  закрыт ДД.ММ (UTC)» — отдельной строкой; оговорка уточнена по замеру
  (критик T8).
