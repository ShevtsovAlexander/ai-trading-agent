## Подход

Три слоя, порядок — **сначала замер, потом постройка** (VISION «Проверка
гипотез на данных до постройки»; R «Риски» 1, 6, 7 и «Не найдено» — объём и
поведение библиотеки не замерялись):

1. **Замер (T1).** lightweight-charts на синтетике 100 тыс. … 5 млн баров:
   время `setData`, память, плавность прокрутки, сохраняется ли позиция при
   добавлении слева. По итогу — гейт человека: нужен ли потолок числа баров
   в браузере (и какой), или «вся история» на 1м помещается.
2. **Бэкенд — кусок истории «до момента».** Новый маршрут отдаёт `CHUNK`
   закрытых свечей с `openTime < before` и ряды индикаторов по ним — тем же
   `compute`-путём: `fetchClosedCandles` + `WARMUP` слева (R «Окно бэкенда»,
   «Разогрев»). Кусок неизменен → кэш без привязки к «сейчас». Учёт веса
   Binance по заголовку ответа — защита от лимита.
3. **Фронт — склейка и догрузка.** Куски хранятся отдельно от основного
   окна (ответ `/market/candles`), показывается объединение по `t`. Опрос
   обновляет только основное окно — история не стирается (R риск 5).
   Подход к левому краю (`barsBefore`, пример L:2366-2389) → следующий
   кусок. Справа — `fixRightEdge` (L:1388-1393). Над графиком — подпись
   видимого отрезка.

Главное свойство, на котором держится честность: **кусок, посчитанный
отдельно со своим разогревом, даёт те же значения, что длинный ряд**
(`WARMUP = 500`, вес затравки ≈ 2·10⁻¹⁷, `market.types.ts:44-48`; тест
`market-data.service.spec.ts:225`). Значит, склейка кусков = один длинный
ряд, PRD крит. 2 проверяется эталоном `technicalindicators`.

## Контракты

**Бэкенд.**
```ts
// market.types.ts
export const HISTORY_CHUNK = 1500; // свечей в куске; +WARMUP 500 = 2 страницы Binance по 1000 (weight 4)

export interface HistoryChunk {
  coinId: string;
  market: string;
  interval: Interval;
  before: number;          // openTime, исключительно: все свечи t < before
  candles: Candle[];       // ≤ HISTORY_CHUNK, по возрастанию
  series: SeriesPoint[];   // series[i].t === candles[i].t
  complete: boolean;       // true — левее свечей у Binance нет (листинг пары)
}

// GET /market/candles/:coinId/history?interval=5m&before=<ms>
getHistory(coinId: string, interval: string, before: string): Promise<HistoryChunk>
```
- `before` — целое, кратное интервалу, `≤ lastOpen` текущих часов; иначе `400`.
- Окно: `[before − (HISTORY_CHUNK + WARMUP)·step, before − step]` через
  `fetchClosedCandles` (R «Паттерны»: берёт любой отрезок); ряды — тем же
  расчётом, что `compute` (`:173-199`), отдаются последние `HISTORY_CHUNK`.
- `complete` — в окне с разогревом нет свечей раньше начала куска (листинг
  внутри куска или кусок пуст; замер R риск 1: BTC/ETH — 2017-08-17, SOL —
  2020-08-11). Не «окно неполное»: при листинге в зоне разогрева кусок
  полный, но левее него свечи есть (решение человека в T3).
  В начале истории разогрева не хватает → первые точки индикаторов `null`,
  как сейчас у короткого ряда (`SeriesPoint` `:64-65`) — честно, не выдумка.
- Кэш истории — отдельный `Map`, ключ `${coinId}|${interval}|${before}`, FIFO
  50 (кусок неизменен; R риск 9 — ключ основного окна не годится).
- **Страж веса:** `fetchClosedCandles` отдаёт вес из `x-mbx-used-weight-1m`;
  сервис хранит последний. Вес ≥ `WEIGHT_GUARD` (4800 = 80 % от 6000, R риск
  2) → `getHistory` отвечает `429 «Лимит Binance — история догрузится через
  минуту»`, **не** трогая Binance. Основное окно и карточку страж не режет:
  дашборд важнее истории.
- Ошибка Binance — `502 «Binance недоступен»`, как `:166-171`.

**Фронт.**
```ts
// chartData.ts
mergeSeries(chunks: HistoryChunk[], main: MarketSeries): MarketSeries
// объединение по t (Map), по возрастанию; при совпадении t — значение main;
// coinId/interval/range — от main: ключ seriesKey не меняется → fitContent
// не срабатывает на догрузке (CandleChart.tsx:215-219)

// hooks/useChartHistory.ts
useChartHistory(coinId, interval, range): {
  chunks: HistoryChunk[];
  loading: boolean; error: string | null; complete: boolean;
  loadMore: (before: number) => void; // before = t самой ранней показанной свечи
}
// сброс при смене coinId|interval|range: кнопка = стартовое окно (PRD крит. 11)

// CandleChart — новые пропсы
onNeedMore: () => void;        // barsBefore < EDGE_BARS (200); не зовётся при ≥ MAX_BARS (100 000)
complete: boolean;             // → timeScale.fixLeftEdge
onVisibleRange: (r: { from: number; to: number } | null) => void; // мс
```

## Поток данных

```
App: load() → chart (основное окно, как сейчас; опрос — только его)
     useChartHistory(coin, interval, range) → chunks
     data = chartShown ? mergeSeries(chunks, chartShown) : null
       → PriceChart → CandleChart (setData; позиция сохраняется — T1/T6)
CandleChart: subscribeVisibleLogicalRangeChange
     → barsInLogicalRange(range).barsBefore < 200 && !complete && !loading
     → onNeedMore() → loadMore(data.candles[0].t)
     → GET /market/candles/:coin/history?interval&before
     → chunks.unshift(chunk) → mergeSeries → data
     → getVisibleRange() → onVisibleRange → подпись «от–до» над графиком
```
Стык: `before` = `t` самой ранней свечи, которая уже есть → последняя свеча
куска = `before − step` (или раньше — дыра Binance, как сейчас, R
«Разрывы»). Дубль невозможен: `t < before`; объединение по `t` страхует
от совпадений с основным окном, которое сдвигается при опросе (R риск 4).

## Trade-offs

1. **Отдельный маршрут, а не `before` в `/market/candles`.** У куска нет
   `range` и есть `complete`; смешивать — ломать `isAllowed`-валидацию
   (`:76-80`) и ключ кэша (`:152`). Имя `/market/history` не берём — оно
   было у снятого маршрута (`backend/CLAUDE.md:79`, `DECISIONS.md`
   2026-10-07); новое — `/market/candles/:coinId/history`.
2. **Индикаторы считает бэкенд, кусок со своим разогревом.** Отвергнуто:
   досчитывать на фронте — дублировать формулы (`indicators.ts` — один
   источник, `DECISIONS.md` 2026-10-19). Цена — +500 свечей на кусок
   (R риск 3); при `HISTORY_CHUNK = 1500` окно 2000 = ровно 2 страницы.
3. **Куски отдельно от основного окна, объединение по `t`.** Отвергнуто:
   дописывать в один `chart` — опрос его перезаписывает (`App.tsx:87`, R
   риск 5).
4. **Сброс истории при смене диапазона.** Кнопка = «показать этот период»
   (PRD крит. 11); держать историю и подгонять вид сложнее, а выигрыш —
   только повторная загрузка из кэша бэкенда.
5. **Страж веса на бэкенде по заголовку Binance**, а не счётчик запросов на
   фронте: вес общий на IP — его тратят и основное окно, и бэктест; знает
   только Binance. Режет только историю.
6. **Потолок 100 тыс. баров в браузере, опрос через `update()`** (гейт T1,
   решение человека 2026-10-22). Замер T1: `setData` и отрисовка после новой
   свечи растут с длиной ряда (100 тыс. — `setData` ≈ 0,2 с + отрисовка
   ≈ 0,09 с, 1 млн — секунды и ≈ 1,8 ГБ), прокрутка и зум при полосе BB по
   видимому — ≤ 4 мс на любом размере. 100 тыс. вмещают 1д/4ч/1ч до
   листинга; 15м ≈ 2,8 года, 5м ≈ 11 мес., 1м ≈ 69 дней — дальше метка
   «глубже — переключись на свечу крупнее». Опрос дописывает/обновляет
   правые свечи через `series.update()` (≈ 0,1 с на 100 тыс. против
   ≈ 0,3 с у `setData`), `setData` — только на смену ключа и догрузку куска.
   Отвергнуто: выгрузка правого края (скользящее окно) — ломает последнюю
   цену, опрос и позицию; 50 тыс. — режет 1ч до ≈ 2020.
7. **`fixRightEdge`, а не своя блокировка** — встроено (L:1388-1393).

## Риски

- **Производительность на миллионах баров** (R риск 6, «Не найдено») —
  закрывает T1; `bandPrimitive` переводится на видимый диапазон (T5, вместе
  с потолком).
- **Позиция при префиксе** (R риск 7) — замер T1: при `setData` с
  добавленными слева барами библиотека сама держит видимый отрезок по
  времени, ручной сдвиг `setVisibleLogicalRange` его ломает — не делаем.
- **Догрузка и опрос в одном `setData`** (критик T1): префикс слева и новый
  бар справа в одном обновлении сдвигают вид на бар — историю и опрос
  применять отдельными обновлениями.
- **Вес Binance** (R риск 2): полная прокрутка BTC 1м ≈ 3 200 кусков ×
  weight 4 = 12 800 > 6 000/мин — страж даёт паузу, история догружается
  дольше, лимит не превышается (PRD крит. 8).
- **Подписи в глубокой истории** (R риск 8) — год в `formatCandleTime`
  затрагивает таблицу и карточку: там свечи текущего года — вид не меняется
  (проверка в T7).
- **Опрос + история:** основное окно сдвигается вперёд, его старая первая
  свеча остаётся в куске или в объединении — дыры на стыке нет (проверка
  T5, известный ответ в `mergeSeries` T4).
