## Подход

Порядок — **сначала замер, потом постройка** (VISION «Проверка гипотез на
данных до постройки», PRD крит. 5):

1. **Замер на истории (T1)** — скрипт в scratchpad, не в репо: история
   funding BTC/ETH/SOL глубиной ≥ 2 лет (`fundingRate` со `startTime`
   постранично, R «Funding»), распределение, как часто бывают выбросы, как
   ведут себя кандидаты меры необычности на ряде, прилипшем к 0,0100 %
   (R, таблица распределения). Итог — запись в `docs/RESEARCH.md` и **гейт
   человека: мера и период «нормы»** (PRD открытый вопрос 3).
2. **Бэкенд — новый модуль `derivatives/`.** Один маршрут
   `GET /derivatives/:coinId` → текущая ставка Binance, мера необычности,
   OI трёх бирж в USD и сумма. Источники — свободными функциями с
   `HttpService` аргументом, как `fetchClosedCandles`
   (`backend/src/binance/klines.ts:26-33`). Источники опрашиваются
   независимо (`Promise.allSettled`, как `news.service.ts:52`): отказ одной
   биржи — пометка в её поле, не 502 на весь ответ (PRD крит. 6).
3. **Фронт — `DerivativesPanel` под графиком** со своей загрузкой и опросом,
   не внутри `load()` (R «Дальние связи»: общий `settled` связал бы
   скелетон графика и карточки с деривативами; опрос `load()` привязан к
   интервалу свечи, `App.tsx:118-121`, а funding от интервала не зависит).

Модуль отдельный, а не в `market/`: у деривативов свои хосты, свои ошибки
и свой кэш; `MarketDataService` уже держит свечи, историю и ограничитель
(`market-data.service.ts:67-80`) — третья ответственность раздула бы его.

## Контракты

### Бэкенд → фронт: `GET /derivatives/:coinId`

```ts
// derivatives.types.ts (зеркало — frontend/src/types/derivatives.ts)
type Exchange = 'binance' | 'okx' | 'bybit';

interface Derivatives {
  coinId: string;
  market: string;              // 'BTC/USDT'
  funding: FundingView | SourceError;
  openInterest: OpenInterestView;
}

interface SourceError { error: string }  // текст для человека, как 502 market

interface FundingView {
  exchange: 'binance';
  rate: number;                // доля, 0.0000809 (= 0,00809 %); premiumIndex.lastFundingRate
  nextFundingTime: number;     // мс, из ответа — не считаем (PRD «Риски»)
  at: number;                  // мс, premiumIndex.time
  stress: Stress | null;       // null — истории не хватило / история не загрузилась
}

// Мера «от нейтральной» (решение человека по T1, docs/RESEARCH.md
// «Funding Binance: к чему мерить «необычность»», 2026-10-27)
type FundingState =
  | 'above'     // > нейтральной: лонги переплачивают
  | 'neutral'   // ровно нейтральная 0,01 %
  | 'below'     // 0 ≤ ставка < нейтральной
  | 'negative'  // < 0: шорты платят лонгам
  | 'unknown';  // интервал выплат не 8 ч — нейтраль не установлена (RESEARCH)

interface Stress {
  state: FundingState;
  // Доля выплат окна «так же далеко или дальше», 0–100: above — со ставкой
  // ≥ текущей; below/negative — ≤ текущей. null при neutral/unknown.
  tailPct: number | null;
  periodDays: 365;             // окно «нормы» — решение человека
  samples: number;             // выплат в окне
  intervalHours: number;       // от последней выплаты до nextFundingTime, округлён до часа
}

interface OpenInterestView {
  totalUsd: number | null;     // сумма доступных бирж; null — ни одной
  exchanges: Array<
    | { exchange: Exchange; usd: number; at: number }
    | { exchange: Exchange; error: string }
  >;                           // всегда три записи, порядок binance, okx, bybit
}
```

- `400` — неизвестная монета (`market-data.service.ts:140-145`, тот же текст).
- Отказ источника **не** даёт 502 — он в поле (`SourceError` / `error`
  биржи). 502 маршрута нет: весь ответ — сборка из независимых источников.

### Источники (`sources.ts`)

```ts
fetchFunding(http, symbol): Promise<{ rate; nextFundingTime; markPrice; at }>
  // GET fapi.binance.com/fapi/v1/premiumIndex?symbol
fetchFundingHistory(http, symbol, startTime, endTime): Promise<{ t; rate }[]>
  // GET /fapi/v1/fundingRate?symbol&startTime&endTime&limit=1000, постранично
  // вперёд по fundingTime + 1, как klines.ts:38-80; по возрастанию
fetchOpenInterestBinance(http, symbol, markPrice): Promise<{ usd; at }>
  // /fapi/v1/openInterest → openInterest (монеты) × markPrice (R «единицы OI»)
fetchOpenInterestOkx(http, instId): Promise<{ usd; at }>
  // /api/v5/public/open-interest?instType=SWAP&instId → oiUsd, ts
fetchOpenInterestBybit(http, symbol): Promise<{ usd; at }>
  // /v5/market/tickers?category=linear&symbol → openInterestValue, time ответа
```

Символы (R): Binance/Bybit — `BTCUSDT`, `ETHUSDT`, `SOLUSDT`; OKX —
`BTC-USDT-SWAP`, `ETH-USDT-SWAP`, `SOL-USDT-SWAP`. Карта — в
`derivatives.types.ts` по `coinId` тех же ключей, что `COINS`
(`market.types.ts:58`); `COINS` не меняем (R «Дальние связи»: 4 места).

Для Binance OI нужен `markPrice` — берётся из того же `premiumIndex`, что и
ставка: один запрос на оба поля. Упал `premiumIndex` → и funding, и
Binance OI — ошибка (честно: без цены монеты в USD не перевести).

## Поток данных

```
DerivativesPanel ← useDerivatives(coinId): опрос 60 с, токен, монета
        │ GET /derivatives/:coinId
        ▼
DerivativesService.get(coinId)
  ├─ coin(coinId) → 400
  ├─ кэш снимка (TTL 30 с, ключ coinId) → отдать
  └─ Promise.allSettled:
       premiumIndex ─┬─ funding.rate / nextFundingTime
                     └─ markPrice → Binance OI (× openInterest)
       история funding (кэш до nextFundingTime) ─→ stress(история, rate)
       OKX open-interest ─→ usd
       Bybit tickers      ─→ usd
     → сумма доступных OI, ошибки — текстом в поля
```

- **Кэш снимка 30 с** по `coinId`: несколько вкладок/опросов не множат
  запросы к трём биржам; OI и ставка за 30 с не меняются заметно.
- **Кэш истории funding — до `nextFundingTime`** выплаты: новая запись в
  истории появляется только на выплате (8 ч, R `fundingInfo`). Точный кэш,
  как кэш свечей «до закрытия следующей» (`market-data.service.ts:299-321`).
  История не загрузилась — `stress: null`, ставка показывается; не кэшируем.
- Опрос фронта **60 с**, без привязки к интервалу свечи.

## Trade-offs

1. **Мера необычности — «от нейтральной», окно 365 дней** (гейт T1,
   решение человека 2026-10-27; `docs/RESEARCH.md`, секция funding).
   Нейтральная — 0,01 % при интервале 8 ч. Текущий интервал — от последней
   выплаты до `nextFundingTime` (по двум последним выплатам отставал бы на
   выплату после смены — критик T3); в окне — только выплаты с шагом 8 ч от
   предыдущей (ставки за 2–4 ч со ставками за 8 ч не сравниваются: SOL год
   после FTX держал бы в окне 101 такую выплату). Сервис берёт историю с
   `now − 366 дн`, чтобы у первой выплаты окна была предыдущая.
   `fundingStress(history, rate, nextFundingTime, now)`. Не 8 ч →
   `unknown`, ставка без оценки (нейтраль на 2–4 ч — допущение на 7
   точках). «Ровно» — `|ставка − 0,0001| < 1e-9` (шаг ставок Binance
   1e-8, критик T1). Ниже — исходные кандидаты до замера:
   - *z-score* (ROADMAP так назвал) — `(rate − среднее) / σ` окна. На ряде,
     прилипшем к 0,0100 % сверху (R: 0 выплат выше за ~167 дней у всех трёх),
     σ мала и среднее под потолком: обычная 0,0100 % станет «+1σ», любой
     минус — «−3σ». Число без подписи вводит в заблуждение.
   - *Процентиль* — «ставка выше, чем в X % выплат окна». Не предполагает
     нормальности, честно к несимметричному ряду, читается без статистики.
     Слабость: при 11–16 % одинаковых 0,0100 % (R) процентиль ровной
     0,0100 % — диапазон; нужно правило для равных (средний ранг).
   - *Итог T1:* z и процентиль называют нейтральную «высокой» (z
     +1,1…+1,7, процентиль 87–99) — отвергнуты; хвост «от нейтральной» —
     1–6 тревог на 118–205 выплат рядом с нейтралью.
2. **Funding — только Binance** (решение человека): история для меры есть
   только у одного источника, который уже в R; у бирж ставки разные (R:
   Bybit SOL 0,0003 % против 0,0082 %) — «средняя по биржам» смешала бы
   разные рынки. Подпись «Binance».
3. **OI — сумма трёх, с разбивкой**, подпись «Binance + OKX + Bybit, не весь
   рынок» (PRD In scope; R: ≈ 15,6 B против 30,5 B у TradingView).
   Разбивка по биржам видна — сумма проверяема глазом (PRD крит. 3).
   Неполная сумма (биржа упала) — помечена «без OKX» и т.п., не скрыта.
4. **Без ограничителя запросов для fapi/OKX/Bybit.** R: у fapi нет
   заголовка веса; лимиты бирж — тысячи в минуту, а с кэшем 30 с и
   историей раз в 8 ч бэкенд делает ≈ 3 монеты × 4 запроса / 30 с ≈ 24 в
   минуту в худшем случае. *Отвергнуто:* переносить ограничитель
   `market-data.service.ts:217-240` — он держится на заголовке, которого
   здесь нет (R «Риски»), и без заголовка вечно пишет `warn`.
5. **Своя загрузка панели, не `load()`** — R «Дальние связи». *Цена:* в
   `App.tsx` два независимых опроса; ошибка деривативов не показывает баннер
   графика, а пишется в самой панели (как `CardError`, `App.tsx:226-230`).
6. **Блок под графиком, полной ширины** между `TopRow` и `BottomRow`, а не
   в `BottomRow`: та держит высоту левой колонкой (`App.tsx:343-350`),
   третий блок ломал бы её. Решение человека — «блок под графиком».
7. **Ставка — `lastFundingRate` из `premiumIndex`** — текущая расчётная на
   ближайшую выплату (меняется до выплаты), сравнивается с историей
   **выплаченных**. Подпись: «текущая расчётная, выплата через …».
8. **История глубины T1 по запросу на каждую выплату.** 90 дней = 270
   записей = 1 страница; год = 1095 = 2 страницы; раз в 8 ч на монету —
   дёшево. Хранить у себя не нужно (PRD Out of scope; DECISIONS 2026-10-20).
9. **Оговорка — фиксированный текст**, не AI: AI в деривативах — out of
   scope PRD. Текст утверждает человек (T7).

## Риски (ссылки на research)

- **Регион/блокировка хостов** (R «Риски», три хоста) — каждый хост
  отказывает отдельно; приёмка T8 — блокировкой по одному.
- **Единицы OI** (R «единицы OI») — Binance в монетах; тест в T2 на
  фикстуре: `98105.814 × 79932.22 ≈ 7.842·10⁹`, не `98105`.
- **Снимки разных моментов** (R) — сумма складывает OI с разницей в
  секунды; `at` у каждой биржи в ответе, на экране не показываем — принято.
- **Формат ошибок бирж не изучен** (R «Не найдено») — разбор успешного
  ответа строгий: нет нужного поля / не число → ошибка источника, а не `NaN`
  на экране. Тест в T2 на испорченной фикстуре.
- **Глубина истории без `startTime` — 500** (R) — `fetchFundingHistory`
  всегда со `startTime`; тест пагинации на фейке, который режет как Binance.
- **Ряд истории с выплатами не через 8 ч** (PRD «Риски») — мера считается
  по записям окна по времени, не по числу «90 × 3»; `samples` в ответе.
- **Нейтраль 0,01 % — константа** (критик T3). `interestRate` в
  `premiumIndex` есть, но история окна посчитана при прежней базовой ставке —
  одно поле не спасает. За 7 лет данных не менялась; принято (решение
  человека 2026-10-27), записать в «Известное» `backend/CLAUDE.md` (T9).
- **`App.tsx` растёт** (R) — панель и хук отдельными файлами; в `App.tsx` —
  одна строка разметки и вынос `classify`.
