## Подход

Два независимых слоя, оба — без изменения данных и логики (`App.tsx:47-125`,
R «Затрагиваемые файлы»):

1. **Палитра и типографика.** Один источник — `theme.ts`: токены
   переименовываются в язык D (`canvas`, `surfaceCard`, `hairline`, `ink`,
   `muted`, `primary`…), добавляются семейства шрифтов и цвета графика.
   Компоненты переводятся по одному; литералы уходят в тему.
2. **График.** `PriceChart` рисует через lightweight-charts: свечи, EMA9/21
   линиями, полоса BB заливкой, шкала цены справа, перекрестие, зум и
   прокрутка. Данные — те же `MarketSeries` (OHLC уже приходит, R
   «PriceChart — текущее устройство»).

Порядок — **сначала добавить, потом убрать** (как TASK-0004): новые токены
рядом со старыми (T1) → компоненты переезжают по одному (T2–T7) → старые
токены, recharts и мёртвые файлы удаляются (T8). На каждом шаге `tsc -b`
зелёный, экран рабочий — человек видит промежуточный вид.

## Trade-offs

1. **Смена библиотеки (lightweight-charts) vs полировка recharts.**
   Выбрано: смена — решение человека 2026-10-21. Цена — императивный код
   (эффекты, ref) там, где сейчас декларативный компонент (R «Паттерны»:
   такого кода в клиенте нет). Плюс: свечи, перекрестие, зум «из коробки».
2. **Полоса BB: свой примитив vs две линии без заливки.** Выбрано:
   примитив (`attachPrimitive`, L:2591) — заливку ввёл TASK-0002
   сознательно. Цена — ~60 строк canvas-кода без внешнего оракула (только
   глаз). Отвергнуто: «area верхней границы + area нижней цветом фона» —
   закрашивает сетку и свечи под полосой.
3. **Разрыв как whitespace-слот vs ничего.** На оси по барам (а не по
   времени) пропуск Binance иначе схлопнется бесследно. Выбрано: один
   пустой слот — разрыв виден, но не пропорционален длине паузы (было
   пропорционально на временной оси recharts). Принимаем: факт пропуска
   важнее его масштаба.
4. **`setData` на каждом опросе vs `update()` последней свечи.** Выбрано:
   `setData` (L:2464 `update` требует, чтобы бар был ≥ последнего — после
   смены диапазона это не так). Видимый диапазон при `setData` сохраняется,
   новая свеча сдвигает его при `shiftVisibleRangeOnNewBar` (L:1443, по
   умолчанию true). `fitContent` — только при смене ключа. Проверяется
   живьём в T5 (зум переживает опрос).
5. **Цвета монет: убрать vs сохранить.** Выбрано: убрать (вопрос 2). Цена
   — монета на экране различима только подписью; принимаем: она и так
   крупно в шапке графика и карточке.
6. **`up/down`: цвета D vs свои.** Старт — цвета D (выбор человека на
   гейте). Риск из PRD «Tailwind-цвета вернут дефолтный вид» принят
   осознанно; запасные варианты — в таблице вопросов.
7. **Шрифты локально vs Google Fonts** — см. «Дополнительно».
8. **Высота графика 200 → 360 px.** TradingView-вид не помещается в 200
   (`PriceChart.tsx:344`): свечи на 288 барах в 200 px — штрихи. Меняет
   высоту экрана; `BottomRow` уезжает ниже — принимаем.
9. **OHLC в легенде — новые числа на экране?** Свечи несут O/H/L по
   определению; без подписи значений перекрестие бесполезно. Это следствие
   решения «свечи», не отдельная фича. Объёмы — нет (PRD Out of scope).

## Риски (ссылки на research)

- **R1 (сек/мс)** — снят контрактом `chartData` (`time = t/1000`); проверка
  в T4 скриптом на известном ответе.
- **R2 (UTC vs местное)** — `timeFormatter` + `tickMarkFormatter`; проверка
  в T5: время свечи под перекрестием = строка таблицы.
- **R3 (разрывы)** — whitespace-слот, trade-off 3; проверка в T4 на
  синтетической дыре (живой дыры Binance в окне нет).
- **R4 (полоса BB)** — примитив, trade-off 2; риск: ошибка координат
  заметна только глазом. Оракул — заливка совпадает с пунктирными
  границами (которые рисует сама библиотека) на любом зуме.
- **R5 (`null`)** — whitespace в контракте.
- **R6 (StrictMode, сброс зума)** — `remove()` в очистке; trade-off 4.
- **R7 (ширина)** — `autoSize` (L:948); проверка ресайзом окна.
- **R8 (`chartShown === null`)** — `setData([])`.
- **R10 (шрифт в canvas)** — после `document.fonts.ready` повторный
  `applyOptions({ layout: { fontFamily } })` — график перерисует подписи.
  Проверка глазом: подписи осей — JetBrains Mono, не системный моно.
- **R11 (цвета в canvas)** — опции строятся из `useTheme()`; критерий 2
  ловит любой литерал grep'ом.
- **R12 (точность)** — `precision: 2` = `round` бэкенда.
- **R13 (бандл)** — замер «до» снят 2026-10-21 на `d380e44`: JS
  **630 863 B**, gzip **192 248 B** (один чанк, предупреждение Vite > 500 kB
  уже есть). «После» — в T8.
- **Новый: узнаваемость ClickHouse** (PRD «Риски») — без их логотипа и
  формулировок; шапка — наше название.
- **Новый: нет внешнего оракула для «красиво»** — критерии 3–6 и 9
  проверяет только человек. Критик (`.claude/agents/critic.md`) проверяет
  измеримое: grep литералов, шрифты в Network, значения легенды vs API.
