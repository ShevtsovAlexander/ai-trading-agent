- [x] **TASK-0007.1: funding на истории (замер, скрипт вне репо) + запись в RESEARCH.md**
  Скрипт в scratchpad: `fundingRate` BTC/ETH/SOL со `startTime` постранично
  за ≥ 2 года (или с листинга). По каждой монете: мин/макс, доля ровно
  0,0100 %, доля выше и ниже, квантили; как часто ставка уходит за
  0,0100 % вверх и ниже нуля, сколько длятся такие эпизоды. Для окон 30 /
  90 / 365 дней: z-score и процентиль текущей ставки и их поведение на
  истории (сколько дней в году «необычно» по каждой мере при порогах).
  - Критерий готовности: таблица по трём монетам и трём окнам; секция в
    `docs/RESEARCH.md` по формату файла (гипотеза, как проверяли — эндпоинт,
    монеты, период, дата, — результат, вывод); рекомендация меры и окна.
  - Оракул: реальные данные Binance; числа — человеку. Повторный прогон
    скрипта даёт те же числа на том же отрезке.
  - **Гейт человека:** мера (процентиль / z / иное) и окно «нормы» — до T3.
    Если данные покажут, что сильных перекосов нет вовсе, — человек решает,
    строить ли меру или показывать только ставку.
  - **Итог (2026-10-27):** история с начала торгов (BTC 7813, ETH 7579,
    SOL 6780 выплат). 0,01 % — нейтральная ставка, не потолок: в росте
    (2020–21, 2024) выше неё 20–45 % выплат, с 2025 — ни разу. z-score и
    процентиль называют нейтральную «высокой» (z +1,1…+1,7, процентиль
    87–99) — отвергнуты как подача. Мера «от нейтральной»: тревог рядом с
    нейтралью 1–6 на 118–205 выплат. Интервал не 8 ч (SOL, FTX 2022) —
    нейтраль не установлена, там ставка без оценки. `startTime=0` у Binance
    = «не задан». Критик: числа сошлись, код мер верен; поправлены потолок
    (менялся), «без ложных тревог» (свойство построения), нейтраль на 2–4 ч
    (допущение), диапазоны. Запись — `docs/RESEARCH.md`.
    **Решение человека: мера «от нейтральной», окно 365 дней.**

**Бэкенд**

- [ ] **TASK-0007.2: источники — `derivatives/sources.ts`**
  Пять функций по контракту плана; символы бирж — `derivatives.types.ts`.
  Разбор строгий: нет поля / не конечное число → `Error` с именем биржи.
  - Критерий готовности (`sources.spec.ts`):
    1) фикстуры — сохранённые ответы curl трёх бирж (BTC/ETH/SOL) → числа
       совпадают с полями ответа; Binance OI = `openInterest × markPrice`
       (`98105.814 × 79932.21962069`), не монеты;
    2) `fetchFundingHistory` на честном фейке (режет по `startTime`/
       `endTime`/`limit` как Binance) — 2300 записей за 3 запроса, по
       возрастанию, без дублей на стыке страниц, защита «страница не
       сдвинулась»;
    3) испорченная фикстура (нет `oiUsd`, `"abc"`) → ошибка, не `NaN`.
  - Оракул: реальные ответы бирж (фикстуры), фейк как у `klines.spec.ts`.
    Каждый тест прогнать против мутанта (красный).

  - Оракул: независимый расчёт (Python/numpy в T1, не этот код). Мутант
    (сдвиг окна на запись / строгое неравенство вместо нестрогого) — красный.

- [ ] **TASK-0007.4: сервис + маршрут `GET /derivatives/:coinId`**
  `DerivativesService`, контроллер, модуль, регистрация в `app.module.ts`,
  `test.http`. Сборка по «Потоку данных» плана: `allSettled`, сумма OI по
  доступным, кэш снимка 30 с, кэш истории до `nextFundingTime`, часы полем.
  - Критерий готовности (`derivatives.service.spec.ts`, фейк HTTP по URL):
    1) все источники живы → форма ответа по контракту, `totalUsd` = сумма
       трёх;
    2) упала OKX → у OKX `error`, `totalUsd` = Binance + Bybit, funding на
       месте; упал `premiumIndex` → funding `error` и Binance OI `error`,
       OKX + Bybit на месте; упали все → `totalUsd: null`, маршрут не 502;
    3) история не загрузилась → `stress: null`, ставка есть;
    4) второй вызов в пределах 30 с — 0 запросов; после 30 с — снимок
       заново, история — нет, пока не прошёл `nextFundingTime`;
    5) неизвестная монета → 400 без запросов.
  - Оракул: известный ответ фейка (суммы и счётчики запросов считаются
    вручную). Мутанты: `Promise.all` вместо `allSettled`, кэш без TTL.
