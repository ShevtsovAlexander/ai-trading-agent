- [x] **TASK-0009.2: сборка `buildWalls`**
  `orderbook/walls.ts` по контракту плана: mid, общий край, сторона от mid,
  ступени, отброс разрезанной краем ступени, сумма и `Σ цена × объём`,
  N крупнейших. Независимый скрипт (Python, вне кода бэкенда) считает
  эталон из той же фикстуры → `expected` в фикстуре.
  - Критерий готовности: на фикстуре трёх монет — совпадение с эталоном
    по всем ступеням и полям (`from`, `coin`, `usdt` ≤ 1e-9 отн., `byExchange`);
    биржа `null` — охват и стены по другой; покупки все `< mid`, продажи
    `> mid`; ни одна ступень не дальше общего края; вне топ-N нет ступени
    крупнее последней нарисованной (критерий 2 PRD).
  - Оракул: эталон независимого скрипта; мутанты (край — дальний, а не
    ближний; стороны без mid; `usdt = coin × середина`) — красные.
  - **Итог (2026-11-02):** `orderbook/walls.ts` — `buildWalls`, `Wall`,
    `Walls`. Цены и шаг — целыми в единицах 1e-8 (деление дробных: SOL
    94.15 / 0.05 = 1882.999…). Эталон — скрипт Python (Decimal, вне репо)
    → `expected` в фикстуре: 9 случаев (3 монеты × обе / только Binance /
    только OKX). Совпадение по всем ступеням: `from`/`to` точно, `coin`/
    `usdt`/`byExchange` ≤ 1e-9 отн. Охват (обе биржи): BTC 77164.7–79062.2,
    ETH 2220.6–2358.46, SOL 42.18–144.16. **Замечено для T6:** крупнейшая
    продажа SOL — ступень 130 при цене 94 (+38 %), за краем графика.
    Мутанты «без деления по mid», «без отброса разрезанной ступени», «при
    равенстве — дальше от цены» на фикстуре были зелёными (такие ступени
    не попадают в топ-10) → добавлены 3 теста с известным ответом на малых
    стаканах. Правило «разрезанная краем ступень отброшена» действует и
    для стороны, отданной целиком (край = конец стакана; так же в эталоне)
    — у неё теряется последняя ступень, на топ-10 не влияет. Тесты:
    `walls.spec.ts` — 24 (всего 231).
    **Критик T2 → решение человека (вариант А):** ступень с mid внутри
    рисовалась целиком и заходила за цену (ETH `[2286, 2287)` при mid
    2286.745 — продажи ниже цены; эталон повторял ту же ошибку правил) →
    обрезка по mid в коде и в эталоне, `expected` пересчитан (4 обрезанные
    ступени: BTC both/binance продажи, ETH binance продажи, ETH okx
    покупки). Свойство сторон ужесточено: покупки `to ≤ mid`, продажи
    `from ≥ mid`. Мутант «без деления по mid только у покупок» был зелёным
    (покупка выше mid в фикстуре одна — OKX ETH, вне топ-10) → тест с
    известным ответом. Находка критика об отбросе последней ступени у
    стороны, отданной целиком, — не выбрана человеком, правило прежнее.
    Мутанты — 11 из 11 красные: край дальний (2), без деления по mid обе
    (2) / покупки (1) / продажи (1), `usdt = coin × середина` (10), ступень
    делением дробных (3), без отброса разрезанной (3), равенство — дальше
    (1), mid по OKX (4), без обрезки по mid продажи (8) / покупки (3).
