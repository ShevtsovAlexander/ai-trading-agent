# Roadmap

Живой список. Обновляется при каждом изменении направления.
Порядок в секциях = приоритет (сверху важнее).

## Сейчас

Активного тикета нет — следующий берётся из «Хотелок» или
«Production-hardening».

## Хотелки (приоритет сверху вниз)

- [ ] **Деривативы: ликвидации** — график ликвидаций по времени, лонги и
  шорты раздельно, периоды 1Д / 1М / 1Г, плюс сумма за 24ч. Образец —
  блок «Деривативы» на странице BTCUSD TradingView (показал человек
  2026-10-27; источник данных там не назван). Это **факт** (уже
  случившиеся ликвидации), не оценка. **Источник не выбран:** история
  ликвидаций у Binance закрыта (`allForceOrders` → 404, 2026-10-27), живой
  поток отдаёт не все события, а копить его у себя — против принципа
  «данные по запросу» (TASK-0004). OKX отдаёт ликвидации без ключа, но
  только последние (~100 штук за ~40 мин, глубже пусто — curl 2026-10-27).
  Кандидат — Coinalyze API: бесплатный ключ (без ключа — 401), история
  ликвидаций по сторонним описаниям, **с ключом не проверено**. CoinGlass API — платный, от $29/мес, бесплатного тарифа нет
  (страница тарифов, 2026-10-27). Проверить до PRD.
- [ ] **Уровни скопления ликвидаций на графике** (карта по цене, где
  *могут* сработать ликвидации; не путать с графиком ликвидаций по
  времени) — **это оценка модели, не факт**: биржи не публикуют, где
  стоят чужие ликвидации; агрегаторы рисуют их из OI и предположений о
  плечах. Против «честной подачи» без явной оговорки. Сначала проверить,
  есть ли честный источник.
- [ ] **Институциональное накопление** — ETF flows + treasuries.
  Публичные данные (не on-chain атрибуция). Новый `WhalePanel`,
  НЕ переиспользовать Wallet/Positions (разная семантика).

## Production-hardening

- [ ] `.env.example` — сейчас нет, без него проект не запустить со стороны.
  Отдельным тикетом **после** миграции: список переменных зависит от того,
  что переживёт удаление торгового ядра.
- [ ] Убрать Postgres/Prisma или найти им применение — с TASK-0004 БД
      никто не читает и не пишет: `PriceSnapshot`/`MarketSnapshot` — архив
      (`DECISIONS.md` 2026-10-20), но `PrismaService` подключается при старте
      бэкенда (`prisma.service.ts:16-18`). Без запущенного Postgres бэкенд
      стартует и всё равно пишет «Подключено к PostgreSQL» — `$connect` с
      адаптером `PrismaPg` ленивый, лог врёт. Замечено 2026-10-21 в TASK-0003.
- [ ] Docker full-stack (сейчас только Postgres)
- [ ] CI: GitHub Actions (lint + build)
- [ ] Health-checks внешних зависимостей (БД, Groq, RSS)
- [ ] AI reasoning только на значимые события (экономия при постоянном сервере)
      Сейчас AI-комментарий вызывает LLM на каждое закрытие свечи
      выбранного интервала (на 1м — раз в минуту на монету): факты свечи
      входят в хеш кэша. Принято — `DECISIONS.md`, 2026-10-07 и 2026-10-20.
- [ ] Таймаут Groq на `/market/view` — сейчас маршрут ждёт модель
      синхронно, промах кэша добавляет 1–1.7 с к ответу с ценой; варианты —
      таймаут или комментарий отдельным запросом (TASK-0004, «Замечено рядом»).

## Отложено

- Polymarket-виджет — мало релевантных данных (`RESEARCH.md`).
  Крипто-рынки там: ценовые производные + новелти, событийных мало —
  порядка 1 релевантного рынка на 100.

## Отвергнуто (не возвращаться без веской причины)

- **Автоторговля** — нет edge (`RESEARCH.md`, бэктест)
- **Тех-индикаторы как автосигнал** — доказано убыточным
- **On-chain атрибуция кошельков** — дорогая инфра (Arkham/Nansen/RPC)
- **Correlation Engine на автоторговлю** — overfitting, иллюзия edge
- **Telegram как источник** — scope creep, RSS покрывает задачу
- **Автотесты UI** — false-green без реального флоу
