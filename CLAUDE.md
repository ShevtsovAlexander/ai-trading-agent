# AI Market Dashboard — корневой контекст

> Этот файл — точка входа для любого агента (Claude Code) и человека,
> открывающего проект. Прочитай его и связанные docs ПЕРЕД любой работой.

## Что это

Информационный дашборд по крипторынку. Агрегирует цены, технические
индикаторы, новости и AI-дайджест в единую картину для принятия решений
**человеком**.

Это **НЕ торговый бот**. Автоторговля отвергнута осознанно — доказано
бэктестом, что технические индикаторы не дают edge (см. `docs/RESEARCH.md`).
Проект переориентирован на инструмент-помощник: показывает контекст,
решение принимает человек.

Рамка: **«триггеры, не команды»**. Дашборд подсвечивает что происходит,
не выдаёт указаний купить/продать.

## Структура репозитория

```
dashboardAi/
├── CLAUDE.md          ← этот файл (навигатор)
├── docs/
│   ├── VISION.md      ← замысел, границы (что делаем / что НЕ делаем)
│   ├── ROADMAP.md     ← текущие задачи и приоритеты
│   ├── DECISIONS.md   ← лог архитектурных решений (почему код такой)
│   ├── RESEARCH.md    ← проверенные гипотезы: TA, Polymarket, поведение LLM
│   └── aidd/          ← артефакты AIDD-флоу (см. ниже)
├── backend/           ← NestJS API (см. backend/CLAUDE.md — как устроен)
└── frontend/          ← React дашборд (см. frontend/CLAUDE.md)
```

## Перед работой прочитай

1. `docs/VISION.md` — замысел и рамки. Не уходи за границы «что НЕ делаем».
2. `docs/ROADMAP.md` — что делаем сейчас, что отложено, что отвергнуто.
3. `docs/DECISIONS.md` — почему приняты ключевые технические решения.
4. Технический CLAUDE.md нужной части (`backend/` или `frontend/`).

## AIDD-флоу (работа над фичами)

Новая фича или крупное изменение проходит через процесс, а не пишется сразу.
Каждая фаза — скилл в `.claude/skills/`, между фазами гейт: человек читает
артефакт и говорит «дальше».

```
idea         → PRD из сырой мысли, заводит тикет   docs/aidd/prd/<ticket>.prd.md
research     → карта кода под тикет (файл:строка)  docs/aidd/research/<ticket>.md
plan         → архитектура + разбивка на задачи    docs/aidd/plan/<ticket>.md
                                                   docs/aidd/tasklist/<ticket>.md
implement    → одна задача за вызов, СТОП на ревью человеком
```

- **`idea`** срабатывает автоматически на формулировку фичи («хочу сделать»,
  «нужна фича», «есть идея»). Остальные три — только явным вызовом.
- **Отдельной фазы `tasks` нет** — tasklist генерирует `plan` вместе с планом.
- **Отдельной фазы `verify` нет** — за проверку отвечает агент `critic`
  (`.claude/agents/critic.md`): `implement` зовёт его после каждой задачи,
  до её закрытия. Критик ищет false-green, отклонение от цели, натяжку;
  он спорит, но не решает — финал за человеком.

Активный тикет — курсор в `docs/aidd/.active_ticket`; каждая фаза берёт
номер тикета оттуда.

## Роли и границы (важно)

- **Человек — арбитр замысла.** Агенты исполняют, человек контролирует
  каждый гейт между фазами и ловит false-green внешними оракулами.
- **Нет агента-надзирателя.** Замысел хранит `VISION.md`, а не LLM.
  Если работа уходит в сторону — якорь это документ, сверяйся с ним.
- **Тесты — только с внешним оракулом.** UI-тесты = false-green,
  их не пишем. Тесты для логики где есть эталон (математика, парсинг).
