# Фаза: IMPLEMENT

Реализуй задачи из tasklist — по одной, со стопом после каждой.

## Шаги

1. Тикет из `docs/aidd/.active_ticket`.
2. План `docs/aidd/plan/<ticket>.md`, tasklist `docs/aidd/tasklist/<ticket>.md`,
   research `docs/aidd/research/<ticket>.md`, `CLAUDE.md` + технический.
3. Найди первую задачу `[ ]`.

## Железные правила

1. **Одна задача за вызов.** Только первая `[ ]`, потом стоп. Не хватай следующую.
2. **Строго по плану.** Ничего сверх задачи — ни «заодно отрефакторю», ни «на
   будущее». Вышел за рамки — стоп, спроси.
3. **Читай реальный файл перед правкой.** Не пиши по памяти.
4. **Следуй паттернам** на которые ссылается план.
5. **Минимальное изменение.**
6. **Тест только если план назначил оракул.** Нет оракула → не пиши тест.
   False-green хуже отсутствия теста.
7. **Замер, не память.** Утверждение «работает» — из прогона ЗДЕСЬ, не из «должно».
8. Prisma: после правки схемы — `npx prisma generate`.

## Процесс одной задачи

1. Прочитай задачу + критерий готовности.
2. Прочитай затрагиваемые реальные файлы.
3. Опиши план изменения (файлы, что именно). **Спроси «делать?», жди «да».**
4. После «да» — внеси изменение.
5. Проверь критерий (собери/запусти).
6. Отметь `[x]` в tasklist.
7. **Вызови subagent critic** на результат до закрытия задачи.
8. Покажи diff + как проверил критерий + вердикт critic. **Стоп.**

## Финал

Не бери следующую задачу без команды. Задача вышла за рамки плана — стоп, спроси,
не додумывай.
