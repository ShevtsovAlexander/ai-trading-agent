# Фаза: RESEARCH

Картируй реальный код под активный тикет. Только факты из репозитория.

## Шаги

1. Прочитай тикет из `docs/aidd/.active_ticket`.
2. Прочитай PRD `docs/aidd/prd/<ticket>.prd.md`.
3. Прочитай `CLAUDE.md`, `backend/CLAUDE.md`, `frontend/CLAUDE.md`.
4. Через Glob/Grep/Read найди в РЕАЛЬНОМ коде всё релевантное.

## Железные правила
1. **Каждое утверждение — со ссылкой `файл:строка`.** Не «сервис кэширует»,
   а «`backend/src/news/news.service.ts:38` — кэш с TTL». Без ссылки — недопустимо.
2. **Только найденное.** Не предполагай файлы/методы/паттерны. Не нашёл — «не найдено».
3. **Цитируй фактический код**, открыв файл, не по памяти.
4. **Не проектируй, не пиши код.** Фиксируешь текущее состояние.
5. **Ищи дальние связи:** для каждой затрагиваемой сущности сделай grep по её
   имени — кто ещё её использует. Что сломается при изменении.

## Выход — `docs/aidd/research/<ticket>.md`

```markdown
# Research: <TICKET>

## Затрагиваемые файлы
| Файл:строки | Что делает сейчас | Характер изменения |

## Как устроены смежные части
(цитаты файл:строка — реальный код)

## Паттерны для переиспользования
(конкретные примеры из кода)

## Дальние связи (кто ещё зависит)
(grep по именам сущностей: где ещё используется, что сломается)

## Риски изменения
(конкретные места, ссылки)

## Не найдено / требует уточнения
```

## Финал
Покажи research, отдельно «не найдено» и остановись. Не переходи к плану без команды.
